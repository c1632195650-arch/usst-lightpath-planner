前后端联通与故障判据

怎么看前端、后端、以及两者的联通是好的；每一种异常反馈分别对应什么问题、怎么处理。下面的端口、地址、返回体均为当前代码实测值，不是回忆。

树 _work_dev（master） 前端 localhost:5173（写死） 后端 127.0.0.1:8000（写死） 课表 127.0.0.1:8765（未装 · 有兜底）
01

联通的四层绿灯

「联通」不是单一状态，是四层依次成立。任何一层没绿，下一层必然红——排查永远从下往上。

  1. L1

    进程没退出

    后端终端停在 Uvicorn running on http://127.0.0.1:8000；前端终端停在 vite 的 Local: http://localhost:5173/。终端回到提示符 = 进程已死。

  2. L2

    端口在监听

    netstat -ano | findstr ":8000" | findstr LISTENING 有输出；5173 同理。没输出 = 该层没起来。

  3. L3

    后端自检接口通

    浏览器开 http://127.0.0.1:8000/api/health，返回 {"ok": true, ...}。这是后端「活着且数据加载完」的硬证据。

  4. L4

    端到端通

    前端页面能打开，提问有回答；F12 → Network 里 /api/chat 是 200。这一层通，才是真的「前后端联通」。

三分钟自检

按顺序跑，第一个红的地方就是问题所在层。

# L2 端口在不在听
netstat -ano | findstr ":8000" | findstr LISTENING
netstat -ano | findstr ":5173" | findstr LISTENING

# L3 后端活着没（期望打印 {"ok": true, ...}）
(Invoke-WebRequest http://127.0.0.1:8000/api/health -UseBasicParsing).Content

# L4 端到端：浏览器开 5173 → 提一个问题 → F12 Network 看 /api/chat 是否 200

看到结论

05

为什么端口是钉死的

前端不经过 vite 代理，而是用写死的绝对地址 http://127.0.0.1:8000 直连后端（src/lib/api.ts，可用 VITE_API_BASE 覆盖）。这是跨源请求，靠后端 CORS 白名单放行，而白名单默认只有 localhost:5173 与 127.0.0.1:5173。所以：前端换端口 → CORS 拦；后端换端口 → 前端连不上。两个端口是同一个契约的两端，日常开发不要改。

唯一需要放开端口的场景是手机连局域网演示，那也用后端环境变量 LIBAO_CORS_ORIGINS 临时白名单，代码一字不动。
