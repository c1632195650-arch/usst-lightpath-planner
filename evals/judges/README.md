# 裁判档（LLM-as-Judge）· 纪律与校准

> P0 阶段**还没接**模型裁判：先跑通「规则判分 + 数据门禁」。这一档是 P1 的接口预留，
> 但纪律必须现在写死 —— 裁判用错方式，评测结果就是噪音，比不评还危险。

## 三类判分器怎么分工（不要互相替代）

| 类型 | 负责 | 成本 | 我们的用法 |
|---|---|---|---|
| 代码判分 | 图谱事实、存在性、检索命中、模式/工具断言 | 0 | **默认首选**，覆盖 golden 的 80% |
| 模型裁判 | 忠实度、相关性、完整性、人设与分寸 | 中 | 夜间档 + 争议样本 |
| 人工 | 校准裁判、仲裁边界、Golden 标注 | 高 | 每周抽 20 条 |

## 六条纪律（来自 LLM-as-Judge 综述与工业实践）

1. **不用同族模型当裁判**：生成用 `deepseek-chat`，裁判改用其它模型族（本地 Ollama qwen 或另一家）。
   自偏好偏差是已证实的系统性偏差，不是理论担忧。
2. **rubric 分维度独立打分**，禁止「给个总分」；G-Eval 式：先检查步骤，再结构化输出分数。
3. **提供 `unknown` 出口**：裁判无法判断时必须能说「不知道」，否则会硬给分。
4. **成对比较要换序跑两次**（A/B 与 B/A），结论不一致记为「不确定」，不许挑一个。
5. **客观题给证据**：判数值/日期/政策时，把「图谱原文 / ★ 速查块原文 / 参考答案」一起喂给裁判
   —— 主观质量交给裁判，客观正确性必须给可验证证据。
6. **成本控制**：批量用本地小模型裁判，只在门禁与争议样本上用强模型；线上采样 1%~5%。

## 校准门槛（达不到就不许进 CI）

| 指标 | 阈值 | 怎么算 |
|---|---|---|
| 与人工标注一致率 | **> 70%** | 20 条人工标注 vs 裁判判定 |
| 排序相关性 | **Spearman ρ > 0.75** | 裁判分数 vs 人工分数 |
| 位置偏差 | 换序结论一致率 > 80% | A/B 与 B/A 两次判定 |
| 裁判模型升级后 | **必须重新校准** | 换版本即视为新裁判 |

## 与门禁的关系

- 确定性判分（本轮已落地）→ **每次提交**跑。
- 模型裁判（P1）→ **每晚**跑，分数写入 `evals/runs/`，不在提交时阻塞。
- 人工 → 只做校准与仲裁，不进自动化。

## 提示词位置

三分维度 rubric 在 `rubrics.md`：忠实度 / 相关性+完整性 / 人设与分寸。
调用方（P1 的 `run.py --suite e2e --judge`）负责：套模板 → 请求 → 解析 JSON → 校验字段。
