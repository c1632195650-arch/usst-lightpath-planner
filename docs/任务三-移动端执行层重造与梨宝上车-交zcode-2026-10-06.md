## 一、背景一句话

**产品定位已翻转**：网页端负责「想清楚」，手机端负责「**做出来**」。当前手机端是「网页端的搬运工」——所有日程块等大平铺、没有时间感、没有待办、没有陪伴。CY 要求把它重造成**执行层的仪器**：当前块成为绝对核心（含时间燃烧条）、待办与目标可随手记录、梨宝以抽屉形式提供陪伴与知识问答、通知从「静默」变成「可见」。

### 1.1 CY 的原话（验收唯一标准）

> "手机app的定位是从各方面提升用户在通过上理生活助手制定计划过后要能切实的方便的执行！app作为一个助手要从各个方面辅助用户践行自己的目标和规划"

> "一登录首先出现一个代办和目标小卡片浮现（作用类似于欢迎页面，反复让用户看到自己的目标和待办）窗口要么自己渐渐消失，要么就要能给用户看到当前是什么时段，非常醒目的事件时间地点（**要有时间燃烧条，可以根据比例标记还有多就事件结束**）"

> "最主要的逻辑关系就是要看到现在的事情（**要大**，竖着握持的时候要能看到能占据核心区域比较大的当前事件事件和地点在合适的位置可以根据日程内容给一些相关小tips（可以从数据库中来，要注意相关性）），然后要看到接下来能做的事情（**占次级视觉地位，但要能看到一点基础信息，要小不要喧宾夺主**）"

> "然后主要交互是在today界面（就是登录后的主界面）要能上下滑动查看**仅仅一天的日程**，不要有画像窗口，课表导入有问题，课表窗口也删掉"

## 三、信息架构硬指标（**验收逐条对**）

### 3.1 Today 页三区（竖持单手，重要性从上到下递减）

```
┌─────────────────────────────────┐
│ ① 目标 + 待办卡（D1）            │← 首屏顶部，约 4 秒淡出
│   目标 1-3 条 / 最近待办 / 中长期待办 │   有到期或逾期 → 转常驻提示条
├─────────────────────────────────┤
│ ② 当前块（绝对核心）              │← 视线第一落点
│   标题 ≥28px（现为 text-base）     │   占屏约 40%
│   地点 ≥16px 次之                 │
│   🔥 时间燃烧条（横向，按已过/总时长）│ ← 本任务新增
│   💡 相关小tips（**插槽**，任务一后接）│ ← 本任务留空位
│   [完成] [顺延 15] 两枚大按钮        │   拇指可达，不进二级页
├─────────────────────────────────┤
│ ③ 接下来（次级·小）               │
│   字号小、只给时间+标题，不抢视线    │   上下滑 = 只看当天
└─────────────────────────────────┘
   折叠到底部：📱 我的执行状态 ｜ ☎ 问梨宝 ｜ ICS 引导 ｜ 白名单引导 ｜ 退出
```

### 3.2 量化硬指标（不是"好看"，是数字）

| 指标 | 硬要求 |
|---|---|
| 当前块标题字号 | **≥28px**（现 `text-base`≈16px） |
| 当前块占屏高度 | **≈40%** |
| 接下来列表项字号 | **≤14px**（明显小于当前块） |
| 燃烧条 | 宽度 = `(已过分钟 / 总时长)`，**带百分比数字**，颜色随进度（绿→琥珀→红） |
| 大按钮高度 | **≥44px**（拇指命中区） |
| 主交互层级 | **1 层**（点当前块直接出按钮，**不进二级页**） |

### 3.3 时间燃烧条规格

```
进度 = (nowMin - startMin) / (endMin - startMin)，钳制 [0,1]
显示：进度条 + 百分比 + 「还剩 N 分钟」（N<1 时显示「即将结束」）
颜色：<33% 绿 · 33-66% 琥珀 · >66% 红
边界：nowMin < startMin（未开始）→ 显示「还有 N 分钟开始」，进度 0
     nowMin ≥ endMin（已结束）→ 不显示（该块已从当前块中排除）
```

**必须抽成纯函数** `burnRatio(startMin, endMin, nowMin) → {ratio, remainMin, phase}`，放`lib/` 并单测（`phase` 三态必测）。
