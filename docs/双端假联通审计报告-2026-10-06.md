## 一、六个断点（按链路顺序，全部实测确认）

```
[网页端] 设备ID ──✗① 无账号 ──✗② 上传开关默认关 ──✗③ 服务器代码过期

    ↓
[云端] /api/sync/state  ←──✗④ 账号体系不通 ──✗⑤ 上传时没有 token
    │
    ↓
[移动端] 账号+token ──✗⑥ 网页端读不到手机登录态
```

| # | 断点 | 实测证据 | 影响 |
|---|---|---|---|
| **①** | **网页端没有账号体系** | `src/App.tsx` 零登录字样；`identity.ts:13` 用 `USER_KEY='usst.libao.user_id'`（**本机 localStorage 设备ID**），`getUserId()` 零网络 | 网页端**无法登录**，也就无法与手机端共用身份 |

| **③** | **服务器代码是10-03 旧版** | SSH 实测 `/opt/usst/app/server/sync.py:46` = **`SCHEMA_VER = 1`**，文件时间 `10-03 03:11`；本地已 2（含 `MERGED_ARRAY_KEYS`/`PRESERVE_KEYS`/`persona`/`todos`） | **zcode 那批同步/待办/评估的服务器侧改动，一行都没部署**。前端传 `schemaVer=2` 会被拒 |

| **⑥** | **反向读取同样断裂** | 移动端读网页端靠轮询同一浏览器 localStorage（`WEB_STATE_KEY='usst-life-assistant-v2'`）——**跨设备无效** | 手机上看不到电脑网页端的排程结果 |

**第 ⑤ 条是"假联通"的典型**：接口 200、代码接线、测试全绿，但**数据永远不流动**。

## 四、🔴 我造成的一处真实污染（必须修）

为出 APK，我写了 `scripts/prep_mobile_dist.py`，它把 **`dist/m.html` 覆写成 `dist/index.html`**（让 Capacitor 包内首屏=移动端）。

| 位置 | `dist/index.html` 现状 | 应有内容 |
|---|---|---|
| **本地** `_work_dev/dist/` | 🔴 **移动端**（`id="mobile-root"`） | 网页端 |
| **服务器** `/opt/usst/app/dist/` | ✅ 网页端（`id="root"`） | 网页端 |

**服务器是干净的**（我同步 dist 是在这次污染之前，且这次没再传）。
但**本地 dist 被污染**：如果现在直接 `tar dist` 部署，**会把移动端传到线上根路径**，让网页端彻底变成手机界面。

**修法**：`prep_mobile_dist.py` 改为输出到**独立目录**（如 `dist-mobile/`），不碰 `dist/index.html`。
**这一条必须在下一次部署前修，否则一定出事。**

## 五、三个必修项（**必须一次做完，不可拆着上**）

### 🔴必修 1 · 服务器代码全量同步 + 重启（**最高优先，不做则前端全部白搭**）
-把本地 `server/`、`scripts/`（含 `method_rag.py`/`health_rag.py`/`rag.py`）、`data/`（`method_kb.db`/`health_kb.db`/`campus_*.json` 等）**同步到服务器**
- **重启后端**（改 `data/` 与 `server/` 后不重启会用旧向量/旧 schema）
- 验收：`/api/sync/state` 返回 `schemaVer = 2`；`eval:method` 在服务器侧 PASS
- ⚠️ 遵守服务器护栏（`docs/overnight-guardrails-mobile-2026-10-03.md` §8）：只 `rsync/scp` 到 `/opt/usst/app/**`、禁 `rm -rf`、回滚动作记日志

### 🔴 必修 2 · 统一身份：网页端接入账号体系
**目标**：网页端能用「昵称 + 密码」登录，token 落到 `usst.mobile.token`（**与移动端同一个键**）。

- 在网页端 onboarding 加登录/注册入口，复用 `/api/auth/register`、`/api/auth/login`
- 登录成功后写入 `usst.mobile.token` / `usst.mobile.user`（**直接复用 `auth.ts` 的 `saveIdentity`，零重复实现**）
- **为什么这样最省事**：`App.tsx:65` 的 `installWebSyncHook({ identity: loadIdentity() })` **已经写好了**，一旦网页端有了 token，它**自动就开始上传**，不需要改 `webSync.ts` 一行
- 同时把 `getUserId()` 的返回改为「账号 userId 优先，无账号才回退设备ID」——保证记忆库/画像能跨端

### 🔴 必修 3 · 打开上传开关并暴露 UI
- `usst.mobile.cloudSync` 默认改为**开**（或首次登录后自动置 `'1'`）
- 网页端给一个显式开关（用户能看到"已连接手机端"状态，而不是隐形魔法）
- **验收判据**：网页端排完计划 → 手机刷新 → **能看到新块**（这是唯一有意义的闭环验收）
