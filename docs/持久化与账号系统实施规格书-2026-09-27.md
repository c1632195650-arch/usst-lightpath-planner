## 二、总体架构

```
浏览器（dist/ 静态页面，React）
   │  同源 HTTP，无 CORS
   ▼
serve.py（127.0.0.1:8000，纯标准库 http.server）
   ├─ 静态托管 dist/（SPA fallback → index.html）
   ├─ /api/db/*      → SQLite data/lightpath.db（数据真源）
   ├─ /api/auth/*    → users / sessions 表（Cookie 会话）
   ├─ /courses、/api/import_pdf → server/timetable_parser（进程内 import）
   └─ files 表登记 → data/uploads/*.pdf（二进制留磁盘）
```

- **一个目录、一条命令、一个进程**：主仓库 100% 自包含；
- **localStorage 降级为缓存层**：服务端为真源；服务离线时网站照常以 localStorage 运行（离线容忍），恢复后按时间戳合并；
- 前端 key 字符串、store 语义、引擎（`lib/planner/**`）零改动。

## 三、数据库规范（data/lightpath.db，进 .gitignore）

### 3.1 DDL

```sql
CREATE TABLE users (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  username   TEXT    NOT NULL UNIQUE,
  pw_hash    TEXT    NOT NULL,          -- PBKDF2-HMAC-SHA256，200000 轮，含随机盐
  created_at INTEGER NOT NULL          -- unix 秒
);

CREATE TABLE sessions (
  token      TEXT    PRIMARY KEY,       -- secrets.token_urlsafe(32)
  user_id    INTEGER NOT NULL REFERENCES users(id),
  expires_at INTEGER NOT NULL          -- 7 天滑动过期
);

CREATE TABLE kv (
  key        TEXT    NOT NULL,
  user_id    INTEGER NOT NULL REFERENCES users(id),
  value      TEXT    NOT NULL,          -- JSON blob 原样
  updated_at INTEGER NOT NULL,          -- unix 毫秒（前端 Date.now() 口径）
  PRIMARY KEY (key, user_id)
);

CREATE TABLE course_records (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  课名 TEXT NOT NULL, 类型 TEXT, 节次 TEXT, 周次原文 TEXT, 周次 TEXT,
  校区 TEXT, 教室 TEXT, 教师 TEXT, 考核方式 TEXT, 学时组成 TEXT,
  周学时 TEXT, 总学时 TEXT, 学分 TEXT,               -- 列照 course_records.json 字段定稿
  imported_at INTEGER NOT NULL
);

CREATE TABLE files (
  path        TEXT PRIMARY KEY,          -- 相对主仓库根
  sha256      TEXT NOT NULL,
  imported_at INTEGER NOT NULL
);
```

### 3.3 同步策略

- **写**：前端 `save(key)` = localStorage 同步写（保底）+ `PUT /api/db` 异步（失败静默降级，不弹错）；
- **读**：启动时 `GET /api/db` 拉该用户全部 kv → 逐 key 与 localStorage 比 `updated_at`，**新者胜**；
- **离线**：serve.py 未启动时所有 `/api/*` 请求静默失败，网站以纯 localStorage 模式运行（= 现状）。

## 四、服务端接口规范（serve.py）

统一约定：JSON、UTF-8；错误 `{ "ok": false, "error": "..." }`；未登录访问 `/api/db/*` 返回 401。

| 端点 | 方法 | 请求 | 响应/行为 |
|---|---|---|---|
| `/api/auth/register` | POST | `{username, password}` | 建号 → 自动登录发 Cookie；用户名重复 → 409 |
| `/api/auth/login` | POST | `{username, password}` | 校验 PBKDF2 → 发 HttpOnly Cookie；失败 5 次/10 分钟 → 429 防爆破 |
| `/api/auth/logout` | POST | — | 删 sessions 行 + 清 Cookie |
| `/api/auth/delete` | POST | `{password}` | 校验密码 → 删 users 行（kv/sessions 由 `ON DELETE CASCADE` 连带清除）→ 清 Cookie；密码不对 → 403 |
| `/api/auth/me` | GET | — | `{ok:true, username}` 或 401 |
| `/api/db` | GET | — | `{ok:true, items:[{key,value,updated_at}...]}`（当前用户全部） |
| `/api/db/{key}` | PUT | `{value, updated_at}` | upsert（key 白名单 = §3.2 清单） |
| `/courses` | GET | — | 从 `course_records` 表输出，**响应格式与原 8765 服务逐字段兼容** |
| `/api/import_pdf` | POST | PDF 二进制 | 存 `data/uploads/{sha256}.pdf` + files 表登记 → 解析入 `course_records` 表 → 响应格式同原服务 |

安全基线：密码明文永不落库；Cookie `HttpOnly` + `SameSite=Lax`；SQL 全部参数化；上传文件按 sha256 命名防路径穿越；服务只监听 127.0.0.1。

### 5.4 首次登录数据并入

「不并入」分支（2026-10-01 补）：**按纯新账号进入** —— 清空本机缓存层后进入该账号（云端为空即干净初始态）。此前「不并入」只关弹窗、不动本机数据，导致新账号读到上一个账号的画像与 `onboarded` 标记（事故：注册新号仍是旧画像）。

### 5.5 同机多账号隔离（本机缓存归属，2026-10-01 补）

**问题**：localStorage 缓存原先**没有归属标记** —— 本机只有一份缓存，换账号/注册新号时旧账号的画像、课表、`onboarded` 全量残留，新账号一进去就读到旧数据；且此后任意一次写入都会把旧数据 PUT 进新账号云端；反过来登录另一个既有账号时，「本地胜」还会拿旧数据覆盖对方云端（跨账号互相覆盖）。

**机制**：本机缓存带一个**归属标记** `usst.local_owner.v1`（`localOnly`，只写 localStorage、**绝不入库**）：

| 时机 | 判定 | 动作 |
|---|---|---|
| 启动 `bootstrapSync()` | 标记 == 当前登录账号 | 本地胜（既有对账逻辑不变） |
| 启动 `bootstrapSync()` | 标记 == 别的账号 | 清本机缓存 → 按本账号云端重建 |
| 启动 `bootstrapSync()` | 标记缺失（老用户首次升级） | **认领**给当前账号，不清（否则误清老用户自己的数据） |
| 登录/注册成功 `adoptAccount()` | 同账号且有数据 | 保持本地胜 |
| 登录/注册成功 `adoptAccount()` | 同账号但本机已空 | 从云端拉回 |
| 登录/注册成功 `adoptAccount()` | 别的账号 / 无标记 | 清本机缓存 → 标记新归属 → 按新账号云端重建 |

**整页重载**：清理或重灌本机缓存后必须 `location.reload()` —— 各 store（`lib/storage`、`userPlanStore`、`goalStore`、`routineStore`…）都只在启动时读一次 localStorage，仅切换 auth 状态不会让它们重新装载，内存里仍是上一个账号的数据。

**边界（本批口径）**：
- 「本地胜」只在归属明确（标记 == 账号）时成立；
- 跨设备同步仍不做（§1.3）—— 标记本身**不上云**正是为此；
- 单机「多设备」不涉及；同机换号的数据安全由各自云端承载（清本机 ≠ 删云端）。

**实现落位**：`src/lib/persistence.ts`（`getLocalOwner` / `setLocalOwner` / `clearLocalCache` / `pullCloudIntoLocal` / `adoptAccount` / `bootstrapSync` 归属门）、`src/features/auth/LoginPage.tsx`（并入/不并入分支接线 + 重载）。守卫见 `tests/accountIsolation.test.ts`。

### 5.6 注销账号（2026-10-01 补）

**入口**：右上角账号菜单，位于「退出登录」**下方**（红色危险样式）。

**语义**：永久删除账号及其全部数据，**不可恢复**。这是 §1.3「忘记密码 = 删账号重来」的落地通道。

**服务端**：`POST /api/auth/delete`，请求 `{password}`。
1. `_user_or_401()` 取当前登录用户（未登录 → 401）；
2. `_verify_password()` 校验密码，不对 → **403，不做任何删除**；
3. `DELETE FROM users WHERE id=?` —— `kv` / `sessions` 两表均为 `REFERENCES users(id) ON DELETE CASCADE`，且 `db()` 已 `PRAGMA foreign_keys=ON`，故**级联清空**该账号全部数据；
4. 清 Cookie（`Max-Age=0`）。

**不做**：课表（`course_records` / `files`）是全局共享资产，不随账号删；不删磁盘 PDF。

**前端**（`AccountMenu.tsx`）：点「注销账号」→ 关闭菜单、弹出确认框（写明永久删除 + 无法恢复 + 无密码找回），要求**重新输入密码**二次确认 → 成功后 `clearLocalCache()` + `clearLocalOwner()` + **整页重载**（回登录页，内存态清空）。

**实现落位**：`serve.py::Handler._auth_delete`、`src/lib/auth.ts::deleteAccount`、`src/lib/persistence.ts::clearLocalOwner`、`src/features/auth/AccountMenu.tsx`。守卫见 `tests/accountIsolation.test.ts`（§5.6 用例）。

### 5.7 冷启动落点闸门（把「基础信息」计入判据，2026-10-01 补）

**问题**（RAY 报）：注册 / 进入账号后**看不到「基础信息」界面**。

**根因**：冷启动落点只看 `onboarded`（旧签名 `initialView(onboarded)`）。而 `onboarded` 属于「引导是否走完」，是**早于**「基础信息」这一步就存在的字段 —— 从 beta-v2 并入的旧快照 / 老账号完全可能 `onboarded=true`、`persona` 齐全，却**从没写过 `usst.libao.basic_info`**（那一步是后加的）。旧闸门把这种人直接送进 `main`，基础信息界面于是永久不可达（实况：账号 `temp` = `onboarded=true` + persona + 无 basic_info）。

**机制**：`initialView` 改为吃两个布尔（纯函数，不读存储）：

| onboarded | hasBasicInfo | 落点 | 理由 |
|---|---|---|---|
| false | 任意 | `welcome` | 引导没走完 → 欢迎页（首次入口不变；「先浏览应用」捷径不受影响） |
| true | false | `basicinfo` | 走完了却缺基础信息（老账号 / 并入的旧快照）→ **补齐** |
| true | true | `main` | 都齐了 → 直进主界面 |

`hasBasicInfo` = 必填四项（称呼 / 年级 / 学院 / 校区）齐全；由**组合根** `App.tsx` 现算后注入（`loadBasicInfo()` 已做逐字段白名单校验，坏数据读出来即空对象，天然判否）。

**补齐后不重答问卷**：老账号只是补「基础信息」，画像还在 —— `BasicInfoStep.onComplete` 在 `state.onboarded` 为真时走 `enterMain()`（直回主界面），为假时才进画像。

**与 AC-10 的关系**：AC-10 说「注册新号 = 空白初始态、`onboarded=false`」——闸门对它是 `welcome`，行为不变；本节只多覆盖「`onboarded=true` 却缺基础信息」这一类先前被漏掉的账号。

**实现落位**：`src/features/welcome/basicInfo.ts::initialView`、`src/App.tsx`（`hasBasicInfo()` + 注入 + `onComplete` 分流）。守卫见 `tests/onboardingMerge.test.ts`、`scripts/basicInfo.test.ts`。

2. 数据源**不新建库表、不加 serve.py 端点**：直接从前端校园图谱 `data/campus_map.json` 中 `type==='宿舍'` 的地标**投影**，落为 `src/data/dorms.ts`（共 33 条：北校 20 / 南校 13）。理由：①图谱本就是唯一真源，`server/campus_network.py` 的校内路网也只认图谱 POI；②守住 **AC-4**（无 serve.py 的离线/vite dev 模式也能用）；③不新增对 CY 侧 `server/`、`data/` 的依赖。
3. 名称用**官方全名**：北校宿舍若用短名会与「南校区第 N 宿舍」视觉撞名（如「第七宿舍」→「北校区第七宿舍」）；`verified:false` 的楼标「（待核）」。
4. **引擎消费不变**：`construct.ts` 只读 `homeBase.name` 替换宿舍类模板 `place`，`homeBase.campus` 引擎**不消费**（`homeBasePlacement.test.ts` 已定性该替换对 golden 零影响）。
5. **占位项不混进列表**：每个 `<select>` 的占位 `<option value="">` 一律 **`disabled hidden`**（只当未选时的框内提示，**展开的列表里不出现**），且**不带「1/2/3」序号**（RAY：展开后不该再看到这类空选项）。文案：「选择校区」/「公寓 · 宿舍」（未选上级时「先选校区」）/「楼栋」（未选类别时「先选类别」）。

**做法（作息滚轮）**：

1. `TimeWheelPicker` 由「五行左右可见」改为**固定三行**（选中 / 上一格 / 下一格），`ROW_H=28`；
2. 环形下标 `ring(i,n)=((i%n)+n)%n` —— 小时 23↔00，分钟 00↔55 / 05；
3. 修「滚轮同时带动页面滚动」：React `onWheel` 是 **passive** 监听，JSX 里 `preventDefault()` 无效（会抛 "Unable to preventDefault inside passive event listener"）→ 改 `useEffect` + `addEventListener('wheel', fn, { passive: false })`，回调内 `preventDefault()` + `stopPropagation()`；用 ref 持有最新 `{h,m,hours,minutes,onChange}`，空依赖只装一次监听。
