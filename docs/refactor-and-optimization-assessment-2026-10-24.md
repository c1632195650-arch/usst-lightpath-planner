# 报告一 · 上理助手现有系统的重构与优化评估

> 生成：2026-10-24（zcode，承 `framework-pivot-research` 与两线方案后的第三批交付）
> **看问题的方式**：过去大量开发是在比赛 deadline 压力下完成的——"能用、能演示、能过门禁"优先。这没错，但会留债。本报告把债盘出来，分清**哪些该重构、哪些只需优化、哪些根本不用动**，并给出"不破坏已有成果"前提下的偿还顺序。
> **总原则（不可违反）**：沿用维护计划的 L0/L1/L2 变更分级 + 反向验证纪律；重构只做"行为不变的搬运"，动行为的部分单独立项；golden / 880+459 断言 / E2E 是安全网，重构前后必须零漂移。

---

## 0. 摘要：先说结论

1. **这个项目不需要"大重构"，需要"五笔定点偿债"。** 引擎、数据、测试、安全、移动端骨架都是健康的（维护计划体检 B+/B-，P0 安全债已还清）。真正的债集中在**三处巨型文件**和**四处工程管线**上。
2. **最大的单笔债：梨宝对话层**。三个文件合计 **5948 行**（LbaoChat.tsx 2483 + libaoIntent.ts 2134 + weekPlanForChat.ts 1331），是 S/T/D/H/交互升级五个批次的赶工叠层。它不会马上出事（测试守着），但**每加一个新功能都在变贵**——Report 2 里一半的新功能都动这里。
3. **第二笔债：周视图单文件**（WeekPlanView.tsx 1341 行，视图+编辑+撤销+诊断条混布）。
4. **工程管线的四个坑**（小而烦，一次修干净）：构建会冲掉 APK、测试目录语义漂移、双后端并存、根目录 200+ 临时文件。
5. **明确不用动的**：引擎算法本体、检索流水线、账号/同步/记忆后端、四闸门体系——它们是资产不是债。

## 2. 分项详评（现状 → 为什么是债 → 方案 → 裁决）

### D1 梨宝对话层三巨头（本报告最重要的一节）

**现状**：`LbaoChat.tsx` 2483 行（双模式对话 UI + 追问链路 + 按钮卡 + 反馈 + 评估入口）、`libaoIntent.ts` 2134 行（意图识别：规则链 + 端点调用 + 时间表达式解析）、`weekPlanForChat.ts` 1331 行（防腐层：把引擎输出转成对话话术）。五个批次（S 批追问链、T 批语义换向、D 批对话管理器、H 批交互升级、批次 0-3）各自往同一组文件里加层。

**为什么是债**：不是写错了，是**所有对话新能力都要进这三个文件**。Report 2 的 A1 偏好学习、A2 多方案、C1 晨报都会动这里；不拆，每个新功能的实施成本都被这个"全文理解税"放大。

**方案选项**：
| 路线 | 做法 | 风险 | 效果 |
|---|---|---|---|
| **A 渐进分域搬运（推荐）** | 按已有测试的天然边界拆：`libaoIntent` → 时间解析/规则链/端点调用三模块；`LbaoChat` → UI 组件（消息流/按钮卡/反馈条）与编排 hook 分离；`weekPlanForChat` → 话术生成与引擎调用分离。**只搬运不改写**，每搬一块跑全量门禁 | 低（行为不变，E2E 77 断言+libao 系列测试守护） | 文件从 2400 降到 ≤500×N，后续功能只碰自己的域 |
| B 状态机显式化重写 | 把对话流重写成显式状态机（dialogManager 已有单容器雏形） | 高（动行为，golden/E2E 大面积重拍） | 优雅但违背"不破坏已有成果" |
| C 只拆"读切面" | 抽 hooks 让 UI 文件变小，逻辑原地不动 | 最低 | 治标 |

**裁决**：路线 A，分 4-5 个独立小批（每批一 commit、一过门禁），排在 Report 2 的 A 组功能**之前**做第一批（只拆 `libaoIntent` 的时间解析子模块即可先还 30% 的债）。**估时：全部 4-6 个半天。**

### D2 周视图单文件

**现状**：1341 行，承担视图渲染、编辑交互、撤销/重做栈、诊断聚合条、ICS 引导多个职责；view-model 层（`weekViewModel.ts`）已存在但下沉不全。

**方案**：继续沿既有 view-model 方向下沉——把"编辑动作与撤销"从视图文件抽成独立模块（有 `userPlanStore`/`planLock` 等测试守护）。**不做**视觉层重写（week-view-design.md 令牌体系刚收敛）。
**估时**：2 个半天。**前置**：无。**收益**：Report 2 的 A2 多方案对比要动周视图，先拆后加。

### D3 App 壳与路由

**现状**：view 用字符串切换，动线规则（引导/直达/回退）散在多个 onClick 里；历史上因此出过"新账号绕过课表导入"的 bug（2026-10-08 修，加了 `startPersonaOrOnboarding` 统一动线）。
**方案**：把"页面 + 进入条件"收敛成一张显式动线表（一个模块集中声明，App.tsx 只做分发）——相当于把那次修复的思路推广到全站。**不动** UI。
**估时**：1 个半天。**风险**：低（v0-v3 动线测试锁着）。

### D4 构建冲掉 APK（半小时根治，性价比之王）

**现状**：`npm run build` 里 vite 重写 `dist/`，把放在 `dist/apk/` 的安装包冲掉（BLOCKERS 2026-10-06 实录，曾导致公网 APK 短暂 404）。
**方案**：APK 存放目录与 vite 输出目录解耦（如 APK 挪到 `dist-apk/` 或 vite `build.outDir` 单独配置），同步改 `version.json` 生成与部署脚本引用。L1 级，带一条回归测试（build 后 APK 文件仍在）。
**估时**：半小时 + 半个半天验证。

### D5 测试目录语义漂移

**现状**：`tests/`（113 文件=engine 套件）与 `scripts/*.test.ts`（=ui 套件）分居两处，新人第一反应是懵的；capability-map 靠扫描弥合，`--check` 在守护。
**方案**：渐进归位——新测试一律进语义目录；存量两套 glob 不动（避免 150 文件大搬家），只把 `package.json` 的 `test:ui`/`test:engine` 描述与 tests/README 讲清。**明确不做**一次性全量搬家（风险收益不成比例）。
**估时**：文档半天，无代码风险。

### D6 双后端并存

**现状**：`serve.py`（根目录，一体化：静态托管+API 转发，本地 8765/8000 习惯）与 `server/app.py`（FastAPI，公网 systemd）并存，CORS 白名单/转发规则两处维护，历史上多次"改了 A 忘了 B"（H 批环境坑实录）。
**方案**：不是删，是**定位声明**——serve.py 明确为"本地一体化开发模式"并在文件头声明"生产行为以 server/ 为准"；把两者必须一致的规则（CORS 源、转发路径）抽成共享配置或互查脚本（CI 里加一条一致性检查）。合并成一个属于 L2，等框架线 M3 后端骨架定型时再评估要不要反向统一。
**估时**：1 个半天。

### D7 存储层

**现状**：多个 localStorage 键分片（应用态 v4、移动端 memoCache/memoOwner、planState、各 feature 自管键），迁移逻辑（v2→v3→v4）散在 `storage.ts` 与各处。
**方案**：L1 的"存储网关"——新增统一 `loadState/saveState` 入口与迁移登记表（老 key 照常读，新写入走网关），新 feature 一律走网关；存量不动。
**估时**：1 个半天。**收益**：以后每次契约升级（schemaVer 3、4…）只改一处。

### D8 同步协议（已列 P3-3，这里只定档期）

**现状**：单向上推（"手机改→网页实时看"不成立）、完全信客户端 `clientUpdatedAt`（只防回退不防未来）。
**方案**：维持维护计划 P3-3（服务端时钟钳制 → revision → 双向），但**档期提前条件**：一旦校方合作（B3-3）有实质进展或宣发材料要讲"多端同步"，P3-3 升为当月必做。纯比赛演示期间现状够用。
**估时**：按 P3-3 原估。**关联**：宣发口径 C10 同步修。

### D9 文档漂移与根目录卫生

**现状**：AGENTS.md §〇 快照停在 10-06（测试数/版本/服务器地址都旧了）；根目录 `_*` 临时文件 200+（已被 gitignore，不影响仓，但影响人和 AI 找东西的效率）。
**方案**：① 快照刷新批（半天，纯 docs）；② `_*` 归档移动到 `_archive/` 子目录（白天人工做，遵守"不删只移"，移动不违反禁删纪律但需 CY 过目清单）。
**估时**：合计 1 个半天（人工）。

### D10 引擎微债（顺手项，别单独立项）

- spec §13.8：`resplit` 拆分方向与窗口违约不被目标函数驱动（算子已实现、缺目标项）——**与 Report 2 的 A2 多方案合并做**（都要动 objective，一次 golden 重拍申报搞定两项）。
- `templates.ts` 仍是地点缺省真源：上理线调用侧显式传 `places`（数据已有 `campus_map.json`），让模板退化为演示兜底——**与框架线 M2 对齐做法**，上理线只改调用点，1 小时。

### D11 / D12：并入既有排期

D11 数据债＝B3-4 批（补爬/全文/题库/effective_to）；D12 移动端拆分维持 L4 立项不动。

## 4. 偿还顺序裁决（供 CY 直接排期）

| 顺序 | 批次 | 估时 | 为什么排这位 |
|---|---|---|---|
| 1 | D4 构建解耦 | 0.5 天 | 半小时修一个反复咬人的坑，任何发版前都值得 |
