## 四、三项技术修复

### 1. 路由判定改看「top3 最高分」而非 top1（重要）

**发现的问题**：数据量翻倍后，排序分经归一化+时效加权，top1 常是「较新但不相干」的文档。
实测「光电杯什么时候开始」：top1 = 0.493（委属公办高校仪器设备项目申报，完全不相关），
而正确答案在 **top2 = 0.700**。路由只看 top1 → 误判为 llm 档。

修复：`top_raw = max(所有候选 raw_vec)`。
raw_vec 是绝对余弦，代表「知识库到底能不能答」，取最大值比看排序第一更准。

**效果**：测试从 42/44 提升至 **44/44**，grounded 档从 3 → 5。

### 2. 索引排除 low_value（行政公示噪音）

之前 `build()` 只排除 `is_dup=1`，**没排除 low_value=1**，
导致「双随机一公开监督检查公示」「招标公告」这类噪音也进索引。
现已修正，并标记 18 条行政公示为 low_value。

### 3. 「核心速查」置顶继续复用

给 7 篇关键文档加速查：通宵供电、医保办法、2026 医保缴费、门禁使用、空调租用、公共浴室、**光电杯**。
