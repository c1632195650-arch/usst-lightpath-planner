## 1. 逐项说明

### 1.1 516 号校门 / 334 号校门 —— 坐标是不是开在正确的位置

| | 我方数据 | 学长站数据 |
|---|---|---|
| 516 号校门 | `keypoint` 31.292147, 121.547838 | 31.294xxx（**距我方 375 m**） |
| 334 号校门 | `keypoint` 31.289131, 121.551793 | 距我方 190 m |

**已有证据（倾向我方是对的）**：R2 量了「门到军工路路面的距离」——

```
他的 516 点       → 军工路路面 195.9 m ｜ 最近具名建筑「第一教学楼」45.8 m
我方 516号校门     → 军工路路面  39.1 m ｜ 最近具名建筑「门卫」11.6 m
我方 334号校门     → 军工路路面  23.7 m ｜ 最近具名建筑「门卫」12.1 m
```

**判据**：一个校门不可能离军工路马路 195 m。**他这个点大概率是把「校区主入口」当成「一教附近的某个口」了。**

**还要核对什么**：我们这两个 keypoint 是人工核对的坐标（优先级最高），但仍需确认是**门柱中心**而不是路口中心。
- 站在军工路上拍照（含门牌号），记录手机定位读数；
- 偏差 ≤ 50 m → 保持不动；> 50 m → 重设 `key_points.json` 并复跑 R2。

### 1.2 老图书馆 —— 现在和第一教学楼**完全重合**（P1）

**现状**：`老图书馆` 在 `campus_map.json` 里没有坐标，靠 `walk_minutes`（「第一教学楼 → 老图书馆 2 分钟」）
推导，而它的 walk_minutes 邻居**只有第一教学楼一个** → 解析出的坐标与第一教学楼**一模一样**：

```
老图书馆      src=walk_minutes  xy=(31.293781, 121.551449)
第一教学楼    src=osm           xy=(31.293781, 121.551449)   ← 同一点
```

**为什么还没坏**：`route()` 的可靠度守卫里有 `hav(...) > 5`（两点相距小于 5 m 就判 `reliable=False`），
所以不会输出「一教→老图书馆 0 米」这种假答案，但**它也确实算不出距离**。

**怎么核对**：zone 写的是「毛主席像和一教后方，湛恩大道与海志中路交叉口东南侧」。走一趟取个点即可。

**判据**：实测点与第一教学楼距离应 > 30 m（它毕竟要走 2 分钟）。取到点后写进
`data/osm/key_points.json` 的 `approx` 段（与 `申二教`、`七公寓` 同格式：`coord` + `basis` + `date`），
O 组再补一条「老图书馆与第一教学楼距离 > 5 m」的断言。

### 1.3 综合楼 —— 弱锚，且和「田家炳」的归属纠缠在一起（P1）

**现状**：`综合楼` 定位来源也是 `walk_minutes`，落点距 OSM「门卫」14.2 m。

**为什么和本清单第 4 项（田家炳）有关**：学长站把「**田家炳**」这个口语词挂在了**综合楼 C 区**；
而**校理学院官网**说理学院教学楼被命名为「田家炳楼」；另有一篇报道称「田家炳综合楼」。
三方说法互相冲突，所以我们**没有**收「田家炳」这个词（收了会把新生指错楼）。

**怎么核对**：走到综合楼各区的门口，看**牌匾/楼名石刻**。
- 若 C 区牌子写「田家炳」→ 给 `综合楼` 加别名 `田家炳`（并说明是 C 区）；
- 若理学院楼（南校 334）牌子写「田家炳楼」→ 给 `理学院楼` 加别名；
- 若两处都有 → 两条都加，但**别名要写清校区**（`田家炳（综合楼C区）` / `田家炳（南校理学院楼）`）。

### 1.4 理学院楼 —— 学长站那个「理学院」在**北校**，我们在**南校**

R2 显示：「理学院」对「理学院楼」偏差 **586.9 m（严重不一致）**，而他的点实际贴着
OSM「行政服务中心（格致堂）」（8.9 m）——即**他把理学院放在北校**。我们放在**南校 334**（OSM「理学院」0.0 m，真实几何）。

**要确认的**：上理理学院是不是只有南校 334 一处？（若北校格致堂那边也有理学院的楼/办公室，就得分两条。）

### 1.5 南校区图书馆 —— 我们有条目，但**锚点是弱锚**

**现状**：`南校区图书馆`（南校 334，标注「管理学院 B 栋同楼」），定位来源 `campus`（弱锚），

### 1.8 申一教 / 申二教 —— 顺序可能对调（1100 基础学院）

**现状**：`申二教` 是 **`approx` 近似锚点**（不是 OSM 具名几何），`key_points.json` 里连 `basis` 都写明：

> OSM 1100 片区具名『教学楼』(31.30141, 121.54224) 北侧约 80 米的另一栋建筑，推断为申二教
> （申一教经 `match_osm` 取具名『教学楼』）。**两楼顺序未经实地核对、可能对调**。

`申二教` 当前 approx：`31.30214, 121.54212`。

**怎么核对**：到 1100 看两栋教学楼的**命名牌**，确认哪栋是申一教、哪栋是申二教。

> ⚠️ **改之前先看这个**：`campus_network.py` 的 `_LAT_1100 = 31.2986` 把「1100 校区」的
> 纬度窗口卡在约 **36 m** 宽（最南 31.29874 ↔ 五食堂 31.298419）。实测若把某个 1100 地点
> 往南挪出窗口，它会**掉出 1100 分组**，排程与就近计算会连锁出错。
> 改完必须跑 N 组（1100）与 `_collapsed` 防塌缩断言。

## 3. 已知的「不改也对」结论（避免下次重复劳动）

- **湛恩纪念图书馆 = 图书馆（图文信息中心）**：同一栋楼（2007 年迁入，主馆即湛恩纪念图书馆）。
  已合并为一条，原名保留为别名 —— 不再需要实地确认。
- **卫生科在本部只有一处（516）**：后勤管理处《校内就医》只列 516 / 1100 / 复兴路三处，
  北校「医务室」与「卫生科」是同一处 → 已合并。南校那处另计（`医务室（南校区）`）。
- **「报到 / 迎新 / 注册」不收**：这三件事的执行方是学工/研工与各学院，不是招生办。
  收了会让「新生报到去哪」指错地点 —— **宁可召回为空，也不给错地点**。
- **学长站的 `library` 点不可信**：它 tags 里抄了招生办的「报到/迎新/注册/入学」，说明这份数据是
  多来源拼接的，**坐标与标签要分别取证**，不能整条采信。
