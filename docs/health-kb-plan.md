# 健康知识库（health_kb）方案与落地记录

> 建立时间：2026-09-21（承接方法库 method_kb 之后）
> 定位：给「排程 + 对话」提供面向**普通健康成年大学生**的健康常识与行为方法，
> 覆盖睡眠 / 运动 / 饮食 / 心理四域，外加一层**安全护栏**。

---

## 一、为什么不照抄方法库

方法库（method_kb）的路线是「检索 → 注入」，健康库不能直接套用，因为两者风险性质不同：

| 维度 | 方法库 | 健康库 |
|---|---|---|
| 说错的后果 | 学得慢一点 | **可能真的伤到人** |
| 主要证据源 | 心理学期刊 / 元分析 | **官方指南**（WHO、CDC、中国居民膳食指南、AASM） |
| 个体差异 | 较小 | **很大**（同问法对不同人答案不同） |
| 失败模式 | 召回不准 | 召回准但**给了不该给的建议** |

所以健康库在方法库基础上加了两层：
1. **架构倒置**：`guard()` 守门在检索**之前**，被判定为危险的查询一条结果都不返回；
2. **编译期过滤**：安全升级（escalate）与争议（contested）条目**禁止**编译进确定性引擎。

---

## 二、技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 存储 | **独立第三库 `data/health_kb.db`** | 不并 `method_kb.db`、不并 `usst_articles.db`。安全语义、证据来源、阈值都不同 |
| 检索 | `scripts/health_rag.py`（FTS5 0.4 + 向量 0.6，无时效衰减） | 复用 method_rag 的分词与向量**实例**（避免第二份 95MB 模型），库与门限仍独立 |
| 门限 | **0.70 / 0.63**（实测标定） | 见「五、门限标定」 |
| 编译 | `compile_health_params.py` → `healthParams.generated.ts` → `planner/health.ts` | 引擎是纯函数、不 fetch、不读时钟，知识必须在**构建期**固化 |
| 个人数据 | **CY 的 BMI / 膝伤 / 睡眠浅不入库** | 库是可复用资产；个性化只走画像侧（persona HEА 轴 + profile） |

## 三、数据模型

条目字段（表 `entries`）：
`slug / type(principle|skill|protocol|safety) / domain(sleep|exercise|nutrition|mental) /
title / summary / principle / steps / parameters / applicable_when / contraindications /
evidence_tier(A|B|C|D) / citation{source,url,year,verification} / status(verified|contested|deprecated) /
escalate / seg_text`

**分布**：35 条 —— 睡眠 11 / 运动 9 / 饮食 7 / 心理 8；证据 A 12 · B 13 · C 10；contested 2；escalate 5。

证据分级：A = 官方指南或权威机构共识；B = 系统综述/RCT/一致性实证；C = 教科书或专家共识；D = 从业者经验。
`citation.verification` 三态：`verified`（本轮检索到并读了出处）/ `canonical`（公认经典但本轮未复核）/ `practitioner`。

## 四、三层安全护栏（`health_rag.guard()`，纯函数、确定性）

| 级别 | 触发 | 行为 |
|---|---|---|
| **L0 urgent** | 胸痛、呼吸困难、晕厥、卒中征象、抽搐、大出血、**自伤自杀意念** | **阻断**：`search()` 返回空；口径 = 立即 120 / **12356** |
| **L1 diagnosis** | 「我是不是得了…」「吃什么药/吃几片/剂量」「帮我看化验单」 | **阻断**：转专业，只帮整理就诊问题 |
| **L2 myth** | 排毒、断食排毒、汗蒸减肥、30 分钟才燃脂、塑身衣、褪黑素、喝酒助眠 | **阻断**：给纠正口径 + 实证正路 |
| **L3 consult** | 头痛、头晕、心悸、体重下降、持续发热、抑郁焦虑等 | **不阻断**：检索照常，结果附「建议尽快就医」提示 |
| **L4 ok** | 其余 | 正常检索注入 |

对话层（`server/app.py::health_context`）：护栏口径即使 **LLM 不可用**也要确定性拼进回答——
这是健康库唯一的硬性降级要求。响应体新增 `used_health / health_level / health_top_raw / health_sources`。

**红线**：不诊断、不解释检查报告、不开药、不给剂量与处方；所有健康回答必须带
「通用参考，不能替代医生」声明。

## 六、编译链纪律

`COMPILE_TARGETS` 显式声明「目标键 ← (条目 slug, 参数键)」，编译期校验：
缺条目 / 缺参数键 / 类型不符 / `deprecated` / **`contested`** / **`escalate`** → 直接报错退出，
绝不静默产出缺省值。

只编译 19 个**通用人群、无医疗风险**的排程参数：睡眠保底 7h、每周 150 分钟中等强度、
每周 2 天力量、久坐 60 分钟打断、6000 步、三餐、盐 ≤5g、添加糖 ≤50g、饮水 1700/1500ml、
蔬菜 ≥300g、奶 300ml、蛋白质基线 1.0 g/kg、负荷周增幅 10%。
**减重速度、蛋白质训练期区间等个体差异大的数值不进引擎**（只在对话层带声明给出）。

## 七、门禁基线与反向验证

`evals/health/golden_v1.jsonl` 42 条（recall 23 / block 12 / consult 2 / reject 5），
`npm run eval:health` 判分，0 LLM 成本。

**基线（2026-09-21）**：recall@5 **0.9565** ｜ MRR **0.9275** ｜ guard_acc **1.0** ｜ block_acc **1.0** ｜ reject_acc **1.0** ｜ consult_acc 1.0 → **GATE PASS**

门限：recall@5 ≥ 0.90、MRR ≥ 0.60、guard_acc = 1.0、block_acc = 1.0、reject_acc ≥ 0.80。

三处反向验证（关掉实现必须变红，全部通过）：

1. **编译链**：`minHours` 7 → 8 → 重灌库重编译 → `tests/health_params.test.ts` 红（actual 8 ≠ expected 7）→ 恢复后 4/4 绿。
2. **护栏**：`HEALTH_GUARD_DISABLE=1` → block_acc **1.0 → 0.0**、guard_acc 0.26、26 条安全失败 → 红。
3. **拒答门限**：`HEALTH_RAW_LOW=0` → reject_acc **1.0 → 0.0** → 红。

## 九、权威来源（verified 部分）

- AASM & SRS 联合共识：成人 7 小时以上（SLEEP 2015，PMID 25979105）
- CDC / HHS：每周 150 分钟中等强度或 75 分钟高强度 + 每周 ≥2 天力量训练；WHO 身体活动实况报道
- 《中国居民膳食指南（2022）》八准则及关键数值（盐 ≤5g、油 25–30g、糖 ≤50g 最好 <25g、
  蔬菜 ≥300g、水果 200–350g、奶 ≥300ml、谷类 200–300g、饮水男 1700 / 女 1500ml、酒精 ≤15g）
- 12356 全国统一心理援助热线（中国政府网 2024-12 通知）
- CBT-I 是慢性失眠一线治疗；GAD-7 / PHQ-9 是筛查与严重度工具，**不是诊断**

**复核补录（M8，2026-09-21）**：
- 咖啡因消除半衰期：**成人 3–7 小时**（原写「约 5–6 小时」→ 已按 Wikipedia/Caffeine（引 DrugBank）改正，
  并补上「口服避孕药等可显著延长」的个体差异说明）→ 升级 `verified`
- 渐进超负荷：负荷递增原则有据（Wikipedia: Progressive overload），
  但**「每周 +10%」是经验区间、不是研究结论** —— 已在条目 principle 里显式说明 → 升级 `verified`（等级仍 C）
