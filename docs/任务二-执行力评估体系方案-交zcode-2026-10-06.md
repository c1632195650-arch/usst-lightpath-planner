## 一、背景一句话

手机端是「**计划执行助手**」——用户在网页端排好计划后，手机要帮助他**真正做完**。但目前 App 只能显示"现在该做什么"，无法回答"**我这人执行力到底怎么样、卡在哪**"。本任务建一套**长期个人提升维度**的评估体系，让用户看见自己的执行趋势，并被指向习惯库里可用的方法。

**本批性质：新增**。评估能力从零建，题库内容来自任务一。

### 1.1 CY 的原话（验收时判断"算不算做对"的唯一标准）

> "手机端不要有画像窗口，但可以有一个窗口专门评估用户的执行力自控力等等多维度设计这种长期个人提升的维度这种（同样也是跟app的定位是绑定的），涉及到评估就需要有数据，有评估体系，这个评估体系也要根据习惯库的权威数据来形成，可以是以题库的形式完成采集，比如用户在设定待办过后根据中长期待办和最近待办分别抽取题库中的题目，（题目目的时为了给评估体系以依据）题目不宜多最多5道，每天打开第一次app的时候都可以弹出来采集一波"

> "先给我生成三个独立任务的不同实现路线和功能差别供我选择" → CY 已选定 **路线 2-A：客观行为数据为主 + 每日 ≤5 题自评为辅**

### 1.2 三条不可违反的设计铁律（来自项目既有纪律）

|铁律 | 出处 | 本任务如何落地 |
|---|---|---|
| **不给"综合总分"** | 项目评估纪律 | 五维**各自独立曲线**，不合成一个数。理由：各维度本可互相补偿（少运动多学习），压成一个数 = 替用户做价值判断 |
| **`unknown` 绝不降级为 `gap`** | 项目评估纪律 | 用户没打开 App ≠ 缺乏自律。冷启动期显示「数据累积中」，**不判gap** |
| **缺项用「不可信哨兵」而不是 0** | 项目评估纪律 | 缺数据时 `confident: false`，分数必须与「可判度」同时出现。只给分数 = 骗人 |

**这三条是硬约束，写代码时必须体现为类型与断言，不是靠自觉。**

## 二、五个评估维度（CY 指定"多维度"，本任务定死）

| # | 维度 | 含义 | **客观数据**（主） | 自评（辅） |
|---|---|---|---|---|
| 1 | **任务完成率** | 近期待办勾选比例 | 勾选记录 / 总数 | — |
| 2 | **拖延指数** | 中长期待办实际完成时间 vs 计划 | 完成时间戳 − 计划完成时间 | — |
| 3 | **连续性** | 习惯/目标的连续天数 | 连续有完成记录的天数 | — |
| 4 | **时间纪律** | 计划块的实际开始 vs 计划时刻 | 块完成时间戳 − 计划开始 | — |
| 5 | **自我报告** | 习惯/执行状态自陈 | — | 每日 ≤5 题 |

**关键设计**：维度 1-4 全部来自**用户真实行为数据**（不是自评），自评只喂维度 5。理由：全是主观的自评数据不可信，且违背「数据与闭环」理念。

## 三、题库设计（核心资产）

### 3.1 题目必须「行为锚定」——这是本任务最容易做错的地方

**❌ 禁止的题型**（自恋题，无法验证，还会强化自我认知偏差）：
- "你认为自己自控力强吗？"（1-5 分）
- "你觉得自己是个有毅力的人吗？"
- "今天的状态如何？"

**✅ 要求的题型**（行为锚定，可与客观数据交叉验证）：
- "今天想开始做某件事时，你**实际**推迟了吗？"（附具体行为选项：没推迟 / 推了 10 分钟内 / 推了 1 小时内 / 推到明天 / 直接放弃）
- "今天有没有出现'想做但不想动'的时刻？"（有 / 没有；若有→是什么任务）
- "过去一周，你**实际**开始做一件拖延任务时，最常的阻碍是什么？"（不知道从哪开始 / 怕做不好 / 太累 / 手机分散注意 / 任务太大 / 不感兴趣）

**判别标准**：一道题如果**任何人都能只靠主观印象选一个满分答案**，就是坏题。

### 3.2 题目抽取规则（按待办类型，闭合可测）

```
用户今日待办 → 分类（作业/复习/运动/作息/社交/其他）
           ↓
从习惯库该类相关条目中抽题
           ↓
题目来源 slug 必须可追溯（存slug，不存题目副本）
```

| 待办类型 | 抽题方向（习惯库领域） | 示例题（行为锚定） |
|---|---|---|
| 作业/学习 | 拖延调控、两分钟启动、任务分解 | "今天写作业时，你是从头开始，还是先做了别的再回来？" |
| 复习/备考 | 间隔效应、提取练习、认知负荷 | "今天复习时，你是先看答案还是先自己回忆一遍？" |
| 运动 | 习惯回路、环境设计、摩擦力| "今天出门运动前，你犹豫了多久？" |
| 作息/早睡 | 环境设计、锚点、反弹效应 | "昨晚到该睡的时间，你**实际**推迟了吗？" |
| 社交/杂事 | 微习惯启动、失败重构 | "今天答应别人的事，你**实际**做到了吗？" |
| 无待办 | 习惯中断处理、目标漂移 | "最近没有在做的事，有没有一个你**其实想恢复**的？" |

**「无待办」也要能出题** —— 否则用户没待办时评估就空了，体系会失效。

### 3.3 硬约束

- **每天首次打开弹一次，最多 5 道**（CY 原话"题目不宜多最多5道"）
- 题目**可跳过**，不强制（强制会让人乱答，数据反而污染）
- 题目**从 habit_kb 抽**（`method_rag.search()` 复用，阈值 0.60/0.50），**不得自造引文**
- 每题存`source_slug` → 用户点"看方法"能跳到习惯库那条
- 已答过的题**不重复出**（同一条目 7 天内不再出）

## 五、暂缓 / 不做（本批明确排除）

| 项 | 理由 |
|---|---|
| **综合总分 / 排行榜 / 等级徽章** | 违反项目铁律，且跨用户比较无意义（用户问的是"我怎么样"，不是"我排第几"） |
| **把评估塞进通知** | 通知只走本地通知，不带知识内容与评分 |
| **画像窗口** | CY 明确「不要有画像窗口」。本任务窗口是**执行力评估**，与画像无关，UI 上不得出现"画像"字样 |
| **实时/连续的行为追踪** | 过度监控。本任务只用**用户主动产生的数据**（勾完成、答題），不采集停留时长/点开次数 |
| **把评估结果用于自动调排程参数** | 本批只做"看见+ 指向方法"。让评估反过来改引擎参数属另一个量级，且需要更多金标 |
| **动 `types.ts`** | 禁改。评估类型放独立文件 |
| **`src/features/mobile/` 以外的 UI** | 本批只动移动端；网页端评估视图属任务三 |
| **等任务一/三未完成就硬上** | 见 P0-1 闸门，宁可 BLOCKED 不凑合 |
