# 光溯校园推广评估方案（2026-10-11）

> 背景：校官方 WeLink 课程表应用停用，出现官方课表触点真空。本文评估「以光溯填补这个缺口、在上理推广到 5000+ 用户」的可行性，并给出推广前的整改清单、合规清单、宣发策略、对校沟通路径与比赛矩阵。
> 依据：仓库现状实测（Explore 摸底，2026-10-11）+ 公开信息调研（来源附文末）。**本文是评估方案，不是开工指令**；其中 P0 整改项落地前需要 CY 拍板排期。

---

## 〇、结论速览（TL;DR）

1. **机会是真的，但要换叙事**：WeLink 停用留下的是「看课表」的缺口，而学习通/第三方课表也能看课表。光溯的差异不在"看"，在"看完之后帮你排出每一天"（排程引擎 + 校园知识 RAG + 梨宝）。宣发主打「**从课表到每天的计划**」，不做"又一个课表 App"。
2. **5000 用户技术上可行，但有 4 道推广前必须迈过的硬门槛**（P0，见 §2/§4）：
   - **HTTPS 缺失**：现在全站裸 HTTP（nginx:80），课表是个人信息，学校看到 HTTP 会一票否决；
   - **LLM/记忆端点无鉴权**：`user_id` 由前端随意传，可横向读取/删除他人对话与记忆（app.py:503-509,1186-1196）；
   - **无限流、无 payload 上限**：一个恶意脚本可打垮服务或撑爆 SQLite；
   - **服务器 2026-10-25 到期**（2C2G 腾讯云），比决赛还早——先续费，再谈推广。
3. **合规是推广的前置条件，不是可选项**：公网服务+APK 分发需要 ICP 备案 + App 备案；收集课表/学号需要隐私政策与用户协议；软著建议本月就报（免费、1-2 个月下证，赶 2027 春季比赛季和上架审核）。
4. **对校沟通走得通，但路径有顺序**：指导老师 → 光电学院（光电杯背书）→ 信息化办公室（WeLink 归口）→ 教务处（数据源头）；**大创立项（每年 3 月申报）是把这一切制度化的最好通道**。第一诉求要小（报备+试点默许），不是要接口。
5. **比赛矩阵**：光电杯（本月决赛）→ 大创（2027-03）→ 计算机设计大赛 4C（2027 校赛 3-4 月）→ 中国国际大学生创新大赛（2027 校赛 5-6 月）→ 挑战杯。软著证书是多数比赛资质审查和上架应用市场的通用筹码。

## 一、机会窗口分析：WeLink 停用意味着什么

### 1.1 已确认的事实

- WeLink 是上理官方融合门户（华为云 WeLink 智慧教育案例校），校内挂了 **174 个应用/校园服务**，由**信息化办公室**（net.usst.edu.cn）负责开户与应用接入；2026 级新生的 WeLink 开通通知也由学校部门统一发布。
- 课程表应用停用 → 官方在 WeLink 里给学生的"每日必看"触点出现真空。
- 教务数据源头是教务处「本科生新版教务系统」（jwc.usst.edu.cn，统一身份认证 + 学号登录），数据本身没有消失，消失的是**呈现层**。

### 1.2 竞品真空是部分的，别误判为垄断

| 竞品 | 能看课表 | 差异点 |
|---|---|---|
| 超星学习通（自带课表） | ✅ | 学生本来就装，教务同步 |
| WakeUp 等第三方课表 | ✅ | 人工导入/抓包导入，纯展示，无规划 |
| 微信小程序课表类 | ✅ | 轻量但功能浅 |

**结论**：单靠"课表展示"留不住人，别人的课表随时能复用。光溯该占住的位置是：**课表 → 每日计划 → 待办/截止 → 校园知识问答**这条链，即「智能决策伙伴」的既有定位（`docs/project-core.md`）。宣发叙事写成「课表停用了？光溯把你的课表变成每天的计划」。

### 1.3 窗口期判断

- **现在（10-11 月）**：需求最痛点期（本学期学生已经没有官方课表入口）——适合小规模种子投放；
- **明年 9 月（迎新季）**：最大放量窗口（2027 级新生入学即无 WeLink 课表）——适合正式推广 + 若届时已与信息化办建立联系，可争取新生季官方渠道mention。
- 中间这两学期用来：修 P0/P1 → 灰度跑数据 → 大创立项 → 拿软著 → 攒试用数据。

## 二、大体量使用下的可靠性评估（5000+ 目标）

### 2.1 基数换算

全校全日制在校生 **28000+**（本科 17000+、研究生 12000+，据学校官网）。5000 注册 ≈ **18% 渗透率**，DAU 按注册的 30-50% 估为 1500-2500。这个量级对一台配置正确的单机是可行的，关键不是"能不能扛"，而是"现在的配置不对"。

### 2.2 容量模型（按峰值场景：开学周 2 小时内 3000 人首次导入+同步）

| 维度 | 估算 | 现状是否够 | 结论 |
|---|---|---|---|
| API 读写 QPS | 写 ≈0.5、读 ≈2-5（SQLite WAL 足够） | ✅ 够 | 单机 SQLite 扛 5000 轻写入用户没问题（account 库已有 WAL+busy_timeout，account.py:63-96） |
| 带宽 | 前端静态资源 1-2MB × 首载 3000 人/日 ≈ 3-6GB/日 | ⚠️ 紧 | 2C2G 小水管（3-5Mbps）开学日首载会卡；静态资源应挂 CDN/对象存储或至少 gzip+强缓存头 |
| APK 分发 | 15-20MB × 下载峰值 | ⚠️ 紧 | 现在走 `http://101.35.253.143/apk/...` 直链，放量当天会挤爆带宽；换 OSS+CDN（月成本几十元） |
| 存储 | 5000 用户 × (课表+计划+记忆 ≈ 350KB) ≈ 2GB | ✅ 够但需运维 | memory 库**无 WAL**（memory.py:32,55），高并发写会 busy 报错；需补 WAL + 每日备份 |
| LLM 成本 | 见下表 | ✅ 可控 | 有抽取式降级兜底，成本上限可控 |

### 2.3 LLM 成本估算（按 DeepSeek 公开价：输入 ¥2/M tokens 未命中、¥8/M 输出；缓存命中更低）

| 场景 | 用量 | 估算成本 |
|---|---|---|
| 灰度期：500 DAU × 2 次/日 | 1000 次/日 | ≈ ¥13/日 ≈ **¥400/月** |
| 推广期：2000 DAU × 3 次/日 | 6000 次/日 | ≈ ¥78/日 ≈ **¥2300/月** |
| 满负荷：5000 DAU × 4 次/日 | 20000 次/日 | ≈ ¥260/日 ≈ **¥7800/月** |

**必须配套**：每用户每日问答配额（如 10 次）+ 全局月预算熔断（超限自动降级抽取式——链路已有，`DIALOG_ENABLED`/降级机制现成）。否则一次公众号爆文就能把月预算打穿。

### 2.4 并发模型的一个真实风险

chat 端点如果走同步 LLM 调用（requests 阻塞），uvicorn 默认单 worker 下**十几个并发提问就会排队**，体感是"梨宝死了"。放量前要改：async 化或线程池 + 并发上限 + 排队提示 + 超时降级。

## 四、安全性评估（推广前硬门槛，学校最在意这里）

### 4.1 P0：必须先修，修不好不要推广

1. **横向越权（最严重）**：`/api/chat`、`/api/memory/facts`、`/api/chat/history`、`/api/memory/reset` 全部无鉴权，`user_id`/`session_id` 由前端 body 传入——**任何知道接口的人可以枚举读取、删除他人的对话与记忆**。修法：这些端点一律从登录令牌解析身份，`user_id` 不接受外部传入；匿名模式如果要保留，改为服务端签发的短时匿名 token。
2. **明文传输**：课表（含学号、身份信息）在公网明文跑，按《个人信息保护法》口径属于对个人信息的不当处理；对校沟通时这是"一票否决"项。上 HTTPS 后：APK 关 cleartext、ICS 订阅 token 从 query 参数改为路径随机串并支持吊销（现在 query 里的 ICS 令牌会被日志/代理记录，sync.py:355-362）。
3. **滥用面**：无限流 + sync payload 无大小上限（sync.py:60-66，`state: dict` 原样入库）→ 一个脚本可撑爆磁盘。修法：slowapi/nginx limit_req + payload 上限（如 512KB）+ 请求体 schema 校验。

### 4.2 P1：上线推广前完成

- 下线/加固公网演示账号 gigity/123456（BLOCKERS.md:152）——弱口令留在生产上是把柄；
- **隐私政策 + 用户协议 + 注销（删除账号与数据）入口**：PIPL 要求最小化收集 + 单独同意；文本不用长，说清收集什么（学号/课表/计划/对话）、存哪（境内云）、存多久、怎么删；
- RAG 侧脱敏网关已有（app.py:166-184，落库与读出双向脱敏）——保持，并在隐私政策里如实描述；
- 日志里不落 token/密码/完整对话（现仅异常摘要，保持）。

### 4.3 提示注入（低优先但要有意识）

RAG 语料是校内公开资讯，投毒面小；保持"检索内容只作上下文、不执行指令"的写法即可，不阻塞推广。

## 五、鲁棒性评估

**优势**：冲突合并已有版本化策略（schemaVer=2，todos/goals 逐项并集 LWW、persona 防写空、旧客户端字段 PRESERVE，sync.py:103-186）；输入侧有脱敏；测试体系防回归能力强（recent fix「待办缓存归属守卫」就是多账号场景被打过的补丁）。

**短板**：

1. **公网 PDF 课表导入不可用**（服务器缺 timetable_parser，BLOCKERS.md:129）——这是推广期的最大功能缺口：5000 人不可能手敲课表，WeLink 又停了。**放量前必须把课表导入在服务器上跑通**（解析"新版教务系统"的课表页/截图/导出文件，二选一先通一个）。
2. **iOS 用户无解**：APK 只覆盖安卓；本科 17000 人按 30-40% 估有 5000-7000 iPhone 用户根本装不了。HTTPS 修好后给 m.html 挂 manifest + service worker 做 PWA「添加到主屏幕」，是零成本覆盖 iOS 的唯一路径（manifest 已有，public/manifest.webmanifest，缺 SW 与 HTTPS）。
3. 异常输入：课表解析对脏数据（重名课、无教室、跨校区）的容错要配一批真实数据用例；
4. 时钟/学期边界：termStart 由客户端传入，用户改错会导致整周计划错位——考虑服务端校验学期日历合理性。

## 六、合规与资质（用户问的"软著备案"等，展开说清）

### 6.1 软件著作权（建议本月就办）

- **机构**：中国版权保护中心（ccopyright.com.cn），**官方登记免费**（2017 年起停征登记费，不要买代办；2026-03 中心已发文整治代办乱象、收紧材料审核）。
- **材料**：①在线申请表；②源程序鉴别材料（前 30 页 + 后 30 页，每页 ≥50 行——建议选 `src/lib/planner/` 引擎核心 + `server/app.py`，最能体现技术含量）；③用户手册或设计说明书（前 30 后 30 页，配截图即可）。
- **周期**：自申请到下证一般 **1-2 个月**（不承诺具体时限）。
- **归属决策（重要，和学校背书直接相关）**：
  - 以**个人（团队成员共同）名义**申请 → 版权在你们手里，学校背书不必然要求版权转移；对外沟通时说"学生自主开发、著作权归团队"即可，学校若未来想采购/推广，再谈授权；
  - 若走**大创立项**，按学校大创管理办法可能约定成果共享——申报前把《知识产权归属》条款看清再签，别糊里糊涂签掉版权；
  - 建议软件全称定「光溯校园智能排程助手软件 V1.0」一类，"梨宝"如需独立保护可后续再登记一条。
- **用途**：比赛资质审查/加分、应用商店上架的必要材料、对外沟通时的信任背书。

### 6.2 ICP 备案 + App 备案（推广合法性的底线）

- 现状是**裸 IP + HTTP + APK 侧载**，一旦放量或对接学校，这就是合规硬伤：按工信部 2023 年通知，**面向公众提供 App 服务（含侧载分发）均需 App 备案**，且 App 备案挂在已完成 ICP 备案的域名之下；
- 路径：买域名（~¥60/年）→ 腾讯云上做**个人非经营性 ICP 备案**（2-4 周）→ 同一平台提交 **App 备案**（备案号要在 App 内展示）；
- 顺带把 HTTPS 一起落（同一个域名 + Caddy 自动证书）。

### 6.3 其他可选资质

- **商标**（第 9/42 类"光溯"）：量级 ¥300/类自办，不急，等推广有起色再办；
- **等保测评**：学生项目现阶段不需要，若未来学校要求代管数据再谈；
- **app 上架应用市场**（华为/小米商店）：需要软著 + App 备案，可作灰度后期的分发升级——商店上架对用户信任度远高于"浏览器下载 APK"。

## 七、宣发策略

### 7.1 姿态红线（先立规矩，防舆情）

1. **永远自称"学生团队作品"，不冒充/暗示官方**；名称、页脚、群公告都写清"非学校官方应用"；
2. 不代替学校发任何通知类信息；不做成绩、评教等敏感功能（那是教务红线区）；
3. 收集数据最小化、政策公开——把 §4 修完再放量，出一次数据口碑事故比不推广更糟。

### 7.2 渠道分层（种子 → 学院 → 校级）

| 层 | 渠道 | 动作 | 目标 |
|---|---|---|---|
| 种子（10-11 月） | 自己班级/社团群、室友、光电杯评委与观摩同学 | 决赛现场演示 + 群内"课表停用了"痛点切入 | 100-300 真实用户，收集真机问题 |
| 学院（11-1 月） | 辅导员、光电学院公众号、实验室师兄师姐 | 带 试用数据+软著受理号 找辅导员转发；学院公众号投稿 | 500-1000，留存放数据 |
| 校级（明年 3-6 月） | 校级学生组织、校园公众号、大创立项身份 | 以"大创立项项目"身份做合规推广 | 2000+ |
| 迎新季（明年 9 月） | 新生群、迎新摊位、若可能→信息化办 mention | 全量推广 | 5000+ |

### 7.3 内容素材清单（决赛材料做完后可复用）

- 60 秒演示视频（决赛视频剪一版：WeLink 停了 → 光溯导入课表 → 生成一天计划 → 梨宝问答）；
- 一页纸介绍（PDF，给老师/辅导员看的：是什么/非官方/隐私承诺/联系方式）；
- 新生群话术（痛点开头，不刷屏，附匿名问卷收集反馈）；
- 反馈渠道：QQ 群 + 群内固定反馈表——**前期 100 个种子用户的反馈比 5000 个注册更值钱**。

### 7.4 关键指标（从灰度期就开始记）

激活数、7 日留存、周计划生成率、梨宝日问次数、崩溃/报障数、LLM 单位成本。这些既是迭代依据，也是**对校沟通和比赛答辩的核心弹药**（"XX 名同学真实使用、7 日留存 X%"比任何 PPT 都硬）。

| 学生工作口 | 新生事务（2026 级 WeLink 开通通知由其发布，fm.usst.edu.cn） | 迎新季推广渠道 | 辅导员体系 |

> 说明：具体"哪位老师负责 WeLink/学习通对接"公网查不到到人，这正常——这类归口通常在信息化办的应用管理科室 + 教务处信息科，**正确做法不是冷邮件盲投，而是通过指导老师/学院党政办引荐**（学院和这两个部门有工作往来）。

### 8.2 路径顺序（每步有明确产出）

```
① 指导老师（现在）
   产出：修改申报书、引荐意愿、大创预立项指导
② 光电学院（光电杯决赛后，拿着名次/评审反馈）
   产出：学院层面"知道并有好评"——这是背书的实际形态
③ 创新创业学院：2027-03 申报大创（市级/校级起步）
   产出：立项身份 + 经费 + 合规外壳
④ 信息化办公室（带着 ①②③ + 试用数据 + 软著受理号）
   诉求从轻到重：报备知情 → 允许学生试点 → 只读课表数据接口/WeLink 轻应用接入
⑤ 教务处（由 ④ 引荐或大创身份引荐，不要裸投）
   诉求：课表数据获取的合规口径（哪怕只是"认可学生自主导入个人课表"）
```

### 8.3 沟通姿态：三带三不带三承诺

- **三带**：带作品（真机现场演示）、带数据（试用人数/留存/故障率）、带材料（一页纸方案 + 隐私政策 + 软著受理号）；
- **三不带**：不带商业诉求、不带"取代学校系统"的说法（口径永远是"官方停用期间的学生自用补充"）、不带未修完的安全洞去演示（HTTP 裸奔截图别出现在任何材料里）；
- **三承诺**：不接入/不留存统一身份认证密码（学生自主导入个人课表，学校零改造零责任）；不冒官方名义；数据境内存储、可审计、随删随销。
- **第一次接触的诉求要小**：不是要接口，是"报备 + 请老师指点"——老师最怕的是学生项目出舆情/出数据事故，把 §4 的整改做完再去，姿态完全不同。

### 8.4 风险边界

- 学校可能采购/自建替代（超星生态、华为 WeLink 新应用）——我们的不可替代性在"规划层"，不在"课表层"；
- 学校可能要求整改或下架——保持"随时可下架的轻姿态"，数据可导出，用户不锁死；
- **不要在拿不到任何官方许可前大规模公开宣称"与学校合作"**。

## 十、多校适配愿景：什么叫"达到系统化"

现在的光溯与"上理"深度耦合的有四处：课表解析、校园知识库（RAG 语料）、校区/地点库（placesPolicy）、作息与学期日历。多校化的最低系统化标准是抽出一个 **SchoolPack（学校配置包）**：

```
school-pack/
  schedule.json      # 作息时间网格、学期日历、校区与教学楼
  parser-profile/    # 课表导入解析配置（按目标校教务系统类型）
  corpus/            # 该校知识库语料 → 复用现有 scripts/ 五步流水线重建索引
  places.json        # 食堂/图书馆/自习空间库
  brand.json         # 名称、人格话术、配色
```

- 可复用资产已经就位：数据工程五步流水线、引擎参数（blankDeficit 等软参数）、画像分层问卷；
- **不要现在动手做**。先在上理拿到 2000+ 真实用户，验证产品成立；明年找 1 所规则相近的友校（教务系统类型一致优先）做第一个 SchoolPack 试金石，跑通"换配置包 = 换学校"再谈系统化。多校是 2027 年的故事，今年的故事是把上理做透。
