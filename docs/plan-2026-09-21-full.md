### P0-1 版本管理抢救 【必要而容易｜最优先】
**核验事实**：`_work_dev` **没有 `.git`**（仅有 .gitignore）；`usst-planner` 是 git 仓库但 **main 0 次提交**、170 个文件未提交。两棵树的 `app.py / memory.py / libaoIntent.ts / weekPlanForChat.ts / LbaoChat.tsx` 互有对方没有的东西（`_work_dev` 有意图层+记忆 M0–M3+单日事件；`usst-planner` 有 method_kb.db + health_kb.db + health_context 注入）。所有近期工作处于**无版本保护**状态，一次覆盖即不可回退。

**具体做法**：
1. `_work_dev` 执行 `git init` + 全量首提交（.gitignore 已有，确认 `data/*.db` 被忽略）。
2. `usst-planner` 把 170 个未提交文件提交到本地分支 `wip/merge-into-dev`。
3. 手工合流：以 `_work_dev` 为基座，把 `usst-planner` 独有的 4 组资产拷入并接线——
   - `data/method_kb.db` + `scripts/method_rag.py` + `scripts/method_kb_data.py`
   - `data/health_kb.db` + `scripts/health_rag.py`
   - `server/app.py` 里的 `import method_rag`、`health_context()` 与 chat 主链路注入点（usst-planner 版 app.py:236/741 的对应段落，合到 `_work_dev` 版 app.py 的 POST /api/chat 前后）
   - `usst-planner\server\app.py` 中记忆端点缺失 → 以 `_work_dev` 版为准，勿反向覆盖
4. 合流后跑 `npm run test:engine`（当前基线 312/312）+ `npm run test:ui`（206/206）+ `python -m py_compile server/*.py`，全绿才提交。

**验收**：两棵树合成一棵带 git 的树；`git log` 有合流提交；三套测试全绿。

## 二、E 组 · 必要而容易（每项 ≤1 天，先做）

### E1 基本信息填写前置 + 字段按下游需求补全
**目标**：一进网站（欢迎页之后、问卷之前）就有基础信息表单。
**具体改法**：
1. 新建 `src/features/welcome/BasicInfoStep.tsx`，插进 Welcome → BasicInfo → PersonaFlow → PersonaResult 流程；`App.tsx` 增加 view 状态 `basicinfo`。
2. `src/lib/identity.ts` 的 `BasicInfo` 扩字段（每个字段都对着下游功能设计，不是乱填）：
   - 现有：`nickname / grade / college / major`
   - 新增 `sleepTime / wakeTime`（时间选择器）→ 直接喂排程 dayStart/dayEnd 与晚自习策略
   - 新增 `sportsFamiliar: string[]` + `sportsWanted: string[]`（熟悉的/想尝试的体育项目，多选）→ **运动模式**的模板选择依据（templates.ts 运动模板族）
   - 新增 `snackPref: '下午茶'|'夜宵'|'都要'|'都不用'` → **小馋猫模式**加餐时段开关
   - 新增 `freeTimeWish: '多留白'|'正常'|'排满'` → 远方/内卷模式的初始推荐
3. 修 `onboarded`：`App.tsx` 初始化 view 时读 `localStorage`，`onboarded===true` 直接进 overview。
4. `buildPhases.ts` 的 `applyPersona` 前加一层 `applyBasicInfo(policy, basicInfo)`：作息写 dayStart/dayEnd；sportsFamiliar 非空 → 运动模板 `enabled=true`。

**验收**：新用户必经基础信息步骤；每个字段能在下游找到消费点（grep 得到）；跳过问卷的"先浏览应用"用户也会被引导补填。

### E2 题库按年级分层（静态分层，不搞模型）
**目标**：不同年级看到不同题。
**具体改法**：
1. `personaBank.ts` 每题加可选字段 `grades?: ('freshman'|'sophomore'|'senior')[]`，缺省=全年级可见。
2. `PersonaFlow.tsx` 的题目序列改为 `BANK.filter(q => !q.grades || q.grades.includes(gradeBucket(basicInfo.grade)))`；`gradeBucket`：大一=freshman，大二大三=sophomore，大四/五=senior。
3. 增补年级专属题（写进 personaBank.ts，挂在现有 8 轴上）：
   - freshman：军训/社团招新/早八适应/第一次离家（→ EXP、SOC、HEA）
   - sophomore：竞赛入门/绩点策略/恋爱社交（→ ACH、SOC）
   - senior：考研 vs 就业 vs 出国/毕设/实习（→ ACH、PLAN、RES）
4. 保留 A03 一致性校验题机制不变。

**验收**：三个年级 bucket 各跑一遍，题目集不同但 8 轴每轴至少 3 题覆盖；`buildProfile` 对缺失题有默认权重（已有一致性标记机制可复用）。

### E3 结果页文案升级：模糊文艺 + 趣味称呼
**目标**：命中原型有一句"模糊但会心一笑"的文艺总结；称呼跟画像/基本事实挂钩。
**具体改法**：
1. 新建 `src/data/personaCopy.ts` 文案库：
   - `ARCHETYPE_BLURBS: Record<archetypeId, string[]>`——每原型 4–5 条变体（如卷王本王：「你的日程表比教务处的还满，但总给周三晚上偷偷留了一格」「别人早八在挣扎，你在早八前已经跑完三公里」），**按周随机/按轴值取**，避免背台词感。
   - `FALLBACK_BLURBS: string[]`——未命中原型（距离 > 0.45）时用放之四海皆准的句子（如「你像一本还没定稿的书，目录已经列好，正文正在犹豫从哪页写起」）。
   - 称呼生成器 `makeEpithet(profile, basicInfo): string`：模板槽位拼接，如 `'{总是把{weekday}排得比谁都满的}{major}人'`、`'{在{meal_radius}范围内坚持寻找最好吃那家的}探索者'`——槽位从 8 轴阈值 + 场景字段 + 基本信息取，保证"有趣而不冒犯"（全部正向/中性词，负向轴值用反差幽默表达）。
2. `PersonaResult.tsx`：顶部加 blurb 区（打字机效果可选）+ 动态称呼；保留"数值不代表好坏"缓解文案。
3. 红线自检：文案库全量过一遍，无"焦虑/摆烂/差"等负向定性（可写一个 10 行脚本扫描敏感词，挂进 `npm run test:ui`）。

**验收**：6 原型 × 3 轴值组合抽查，无负面表述；未命中路径有兜底；同 profile 二次生成文案可变。
