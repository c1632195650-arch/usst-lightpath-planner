## 4. 可着手的六个维度

> 按"投入产出比"排列，非按技术难度。

### 维度 A —— 让进度「可见」（最高优先，成本最低）
1. 提交并推送，让远程反映真实进度（当前 38 提交 + 577 行悬空）
2. 修 `AGENTS.md` 两处滞后：称"已收敛为单入口"（实际 `WeekView.tsx:53` 仍用 `lbaoRecommend`）；数据写 255/910（实际 515/1645）
3. **清除双轨残留**：`WeekView` 改走 `buildWeekPlan`

### 维度 B —— 补齐「记忆点」的可视化（演示价值最高）
1. **学期阶段时间轴 + 留白率曲线** —— 把"考试周留白不降反升"画出来
2. **留白率滑块接线** —— 让评委亲手拖，即时看到周计划变化
3. "今天不想动"重排

> 这三件加起来是**产品最有力的 30 秒**：拖滑块 → 留白变多 → 画面说话。

### 维度 C —— 排程引擎深化（技术含量最高）
1. P1 求解器（`construct` → `objective` → `improve` → `solver` → `explain` → golden）
2. P2 动态能力：增量重排 / 滚动视野 / `fromNow`
3. 补 `places.ts` 的课程楼 —— 现 `campusOfPlace` 对国合楼/卓越楼恒返回 `null`

> ⚠️ **前提**：D-4（消费方接入时机）须先定。否则改完无人验证，验收只能退化为单测覆盖。

### 维度 D —— 梨宝从「能用」到「可证」
1. 意图层正则 → **工具调用**（问路、排程、检索成为可调工具）
2. 评测升级：从"断言 `route`"到"**断言答案**"
   - 现存证据：问"今年什么时候放寒假"答"没找到确切日期"、同一信息换个问法又答对"1月25日"，**两条都判通过**
3. 补齐未测维度：事实正确性 / Faithfulness / 记忆复用 / 人格一致性 / PII / 提示注入
4. 记忆层端到端实测（PR #4 已接线，尚无真实多轮验证）

### 维度 E —— 产品健壮性
1. **PDF 课表导入**（演示不能依赖未安装的外部服务）
2. 期末倒计时 T-21/14/7/3
3. 空态 / 错误态 / 离线态走查

### 维度 F —— 参赛交付（时间最紧，不可压缩）
- **9/28 报名截止**（今日 9/15，**余 13 天**）：申报书 + 演示视频
- 10 月底决赛：PPT + 现场演示脚本

## 5. 建议优先级（13 天倒排）

| 优先级 | 事项 | 理由 |
|---|---|---|
| **P0 · 本周** | 提交推送 + 修文档 + 清双轨（维度 A） | 1–2 小时的事，却是所有后续工作的地基 |
| **P0 · 本周** | 启动申报书初稿（维度 F） | 硬截止 9/28，材料写作不可压到最后三天 |
| **P1 · 下一步** | 阶段时间轴 + 留白率滑块（维度 B） | **记忆点的可视化载体**，答辩最有力的画面 |
| **P1 · 并行** | 排程 P1 求解器（维度 C，B 主攻） | 技术最出彩；需先定 D-4 出口 |
| **P2** | 梨宝工具化 + 答案级评测（维度 D） | 决定副线能否独立成为亮点 |
| **P2** | PDF 导入 + 倒计时（维度 E） | 演示鲁棒性 |
| **P3** | 引擎 P2 动态能力 | 加分项，非必需 |

### 核心判断

> **距报名仅 13 天，演示可见性 > 算法深度。**
>
> 排程 v2 的求解器重构是全项目技术含量最高的工作，但它是**引擎内部**的改进 ——
> 做完之后用户看到的变化是"计划更顺了"，而不是"多了一个功能"。
> 在没有可见出口前投入 P1，答辩现场将无法呈现。
>
> **建议**：先用 1–2 天把「阶段时间轴 + 留白率滑块」做成可演示的画面（记忆点落地），
> 再让 B 全力推求解器；两者不冲突，且互为支撑（求解器让滑块拖出来的计划更可信）。
