## 一、这个项目是什么

**一句话**：一个"懂上理"的智能决策伙伴——它认识你的课表，了解上理工的真实生活细节，然后把你的一学期"投影"成一束可以看见的光。

**产品名的来处**：「光溯」= 光 + 溯源。你在**光电**学院，第 18 届光电杯的主题是「智逐光影，溯梦未来」。所以光不是硬贴的视觉风格，是这个项目自带的 DNA。

### 定位的三次校正（重要）

这个项目不是一开始就长这样的，它走过三次关键转向：

**第一阶段：反内卷排程工具**
最初的 PRD 写的是一个纯前端的排程 App：导入课表 → 测学习画像 → 把学期切成五个阶段 → 排出每周日程（带"刻意留白"）→ 期末倒计时冲刺。当时的架构红线是"纯前端、无后端、不做爬虫、数据不出设备"。核心卖点是"期末越近，留白率反而回升"——用留白对抗内卷。

**第二阶段：梨宝校园 AI 助手**
推进过程中，实际长出来的是另一条线：FastAPI 后端 + 本地 RAG + 校园知识库。梨宝成了一个能问答的校园百事通——问"医保报销比例""宿舍能不能用大功率电器""光电杯什么时候报名"，它能引用官方文件回答。这时候"纯前端"的红线已经被打破了，因为你要的"人性化、智能化、贴心"，本质是"伙伴"而不是"工具"，规则引擎撑不起"结合画像判断你该科研还是比赛"这种推理。

于是架构拍板：**走有后端**。代价是放弃了"数据不出设备"这个隐私钩子，换来的是真正的智能。

**第三阶段：懂上理的智能决策伙伴（当前）**
你进一步推翻了"排程是主干"这个判断。理由很实在：排程引擎和"强制留白"只是一种视角、一种输出形式，不该喧宾夺主；真正的核心应该是"足够懂上理、足够贴心，能对上理学子高度场景化、个性化的需求给出量身定制的引导"。

于是重新定义：

- **排程**降级为能力之一（一种输出形式）
- **留白**只是排程里的一个可选策略，不是灵魂
- **学期阶段划分**应由画像驱动（学得慢的人期末要提前，新生迷茫时该给的是探索清单而不是日程表）
- **智能边界**成为最重要的设计原则

### 智能边界四层（核心设计原则）

你担心的"自作主张、喧宾夺主"，落到产品上就是这四层——越往上越不能替用户拍板：

| 层 | 举例 | 我们该做的 |
|---|---|---|
| 信息层 | 保研看绩点、排名、科研、竞赛哪些指标 | 直接给事实，无争议 |
| 引导层 | 打比赛有哪些节点、各什么时候开始 | 给结构化路径，帮他看清路 |
| 建议层 | 结合你高数偏弱+想保研，建议先稳绩点，比赛选光电杯试水 | 给倾向 + 讲理由 + 留余地 |
| 决策层 | 你今天就别打球了去刷题 | **绝不替用户下最后决定** |

一句话：**梨宝可以递给你一张看得懂的地图、陪你走一段、给你指几个方向，但方向盘永远在用户手里。**

## 二、整个开发过程

### 9 月 7 日 · 起点

搭出第一版可交互 Demo（三 Tab：月历 / 梨宝 / 画像），但核心还是模拟数据，没有后端。

### 9 月 8 日 · 数据与智能层（密集推进）

这一天的产出构成了项目的地基：

1. **初代梨宝**：前端 Tab + FastAPI 后端打通，能问答（RAG）也能推荐（规则），无 Key 时自动降级为抽取式
2. **检索升级**：jieba 分词 → FTS5 BM25（权重 0.4）+ bge-small-zh 向量余弦（权重 0.6）× 时效因子
3. **人格注入**：梨宝的完整人设（数字闷骚梨、口头禅、反内卷斗士、括号小声 bb）写进 system prompt
4. **数据工程流水线**：采集 → 清洗 → 去重 → 索引 → 验收，共五步
   - 起点 255 篇（公众号 + 官网）
   - 你直接提供 60+ 链接，补到 308 篇
   - 补齐 P0 三大缺口（体育馆 / 宿舍 / 图书馆），313 篇
   - **依据"全品类校园平台汇总"挖出 20+ 权威官网**，校内 IP 直连全部可达，一轮大采集到 **515 篇主条目、1645 个向量块**
5. **三项关键技术修复**（都很关键）：
   - 「核心速查置顶」：把校历、借阅规则这类高价值文档的关键数值提到正文最前面，否则 chunk 切分会把它埋在中间，LLM 只看到后半段就答错
   - 「查询扩展」：16 条口语→官方术语映射。起因是问"宿舍能用大功率电器吗"，梨宝答"没查到官方明文"——但库里其实有 400W 的规定，是口语词和官方术语对不上
   - **FTS5 空格是 AND 语义**：扩展词不能直接拼在原查询后（会导致零召回），得让扩展词单独走 OR 召回再打折扣
6. **路由修复**：数据从 313 涨到 515 后，top1 常是"较新但不相干"的文档。改成取 top3 里最高的 raw_vec 做判定，测试从 42/44 回到 **44/44**
7. **校园空间图谱**：60 个 POI + 29 条步行关系 + 官方 17 条路段。三教定位是官方实锤（勤勉大道×海晏路口北，与第一食堂同在海远中路沿线）——这让"三教下课去哪吃"从诚实兜底变成了精确回答

**测试**：9 组（A–I）共 44 轮，**44/44 路由符合预期**。

## 三、你想实现的前端效果

### 一句话画面

**在一间昏暗的房间里，一束光从右下方射入悬空的三棱镜，在玻璃内部折射之后散开成彩色的光，把正对你的整面幕墙照亮——幕墙上显现的不是图片，而是你这一周的排程。**

### 为什么是"光"（不是随便选的风格）

你当时的要求是"打开想象力，要么从时间的意象出发，要么从时间的物理特性出发，要么二者结合，要做就做史无前例"。

**物理这一路**：

- 相对论时间膨胀 → 专注的 2 小时 ≠ 摸鱼的 2 小时（主观时间≠物理时间）
- 熵增定律 → 一天就是熵增过程，好排程是减熵而不是填满
- 麦克斯韦妖 → 梨宝就是那只帮你对抗混乱的小妖
- 光的色温 → 晨光冷白、正午暖白、黄昏橙、夜蓝，人的精力本就有色温曲线

**人文这一路**：

- 柏格森的"绵延"（durée）：心理时间 ≠ 物理时间
- 牛顿的三棱镜：白光本是七色混合，棱镜只是让它显形

**为什么最终选了"棱镜分光"**：因为它同时吃透了两路，而且是这个项目**自带的意象**——「光溯」= 光 + 溯源，你在光电学院，光电杯主题就是「智逐光影，溯梦未来」。光不是贴上去的装饰，是这个项目的原生意象。

### 画面构成（v9 定稿）

**1. 幕墙（视觉主体）**
正对用户、占据主视野的一块 5.5 × 2.9 米的投影幕。上面是排程：横向是时间，每一个色块是一件事（高数、C语言、午饭、自习、实验、运动……）。

关键设定：**色块的宽度 = 体验密度，不是物理时长**。同样两小时，专注的高数段就宽，摸鱼的时段就窄。这个设定比"留白"高级——它不教育用户"你该休息"，而是让他自己看见密度。

**2. 三棱镜（控制器）**
浮在画面右下方的一块玻璃三棱柱。它是"调整排程的旋钮"：转它，光就变，幕墙上的排程也跟着换一版。它是真实的玻璃质感——有折射、有内部光路、边缘有高光反射。

**3. 入射光**
一束细白光从画面右下角射进来，打进棱镜。光口有一点克制的暖色光晕，标示"光从这里来"。

**4. 投影示意光束**
三条宽而淡的彩色光从棱镜的三个面分别射出，扫向幕墙外侧与下方的地面。**它们刻意不打到幕墙上**——因为真实的投影演示里，你看的是幕布上的内容，而不是穿过空气的光柱。这些光束只负责给出"光从棱镜指向幕墙"的方向感。

**5. 外沿彩色光晕与整体染色**
幕墙框外渗出柔和的彩色光晕，幕布本身也有一层极淡的暖冷渐变染色——像是整个房间都被这束投影光染上了颜色。但绝不影响表格内容的可读性。

**6. 静态尘埃**
空气里悬浮的细小颗粒，让光柱有了"体积"和"空气感"。它们静止不动（刻意不做飘落）。

### 交互

- **拖拽** → 旋转 / 俯仰棱镜，松手后光路按新姿态重排
- **点「切换排程」** → 棱镜转一整圈，幕墙上的旧内容闪暗，新版像光一样从左侧扫入；同时光束颜色与外沿光晕自动换成新版本的模块色
- **鼠标移动** → 相机有极轻微的视差，像你在亲手操作一台光学仪器

### 最重要的一条：克制

你最后给的九条要求，核心其实是同一句话：**这是高精度光学演示中的投影模拟，不是科幻激光特效。**

具体落到：棱镜本体必须始终清晰可见（不能被光效糊住）；光束不得穿过幕墙前方、不得遮挡课表；没有呼吸灯、没有光束摆动、没有粒子飘落；课程表画面必须稳定清晰完整。

这条约束很关键——它把一个"炫技的光效 demo"变成了一个"可信的产品界面"。

## 四、它为什么站得住（差异化）

**通用排程 App 做不到的，是每一块都有"上理的具体坐标"。**

不是"12:00 吃饭"，而是"高数在三教下课，出来走 3 分钟就是第一食堂，今天有酱鸭"。不是"去自习"，而是"湛恩纪念图书馆 7 点开门， Welink 预约座位"。不是"可以打比赛"，而是"光电杯 9 月 28 日 24:00 截止报名，10 月中上旬初评，官方群 221225591"。

这些细节之所以能答出来，是因为背后有 **515 篇真实的上理官方文档**（保研推免办法、竞赛认定、医保实施办法、宿舍管理条例、国际交流项目、校历……）和一个 **60 个 POI 的校园空间图谱**。这正是你从第一天就在打的地基——数据不是附属品，它是这个产品能"贴心"的唯一原因。

## 五、当前状态与接下来

**已完成**：数据层（515 篇 + 空间图谱）、智能层（梨宝三档路由 + 分层记忆 + 44/44 测试）、视觉层（Newton v9）、输入层（队友的课表导入，PR #1 已合并）。

**中间的缺口**：队友的课表导入产出 `Schedule`，Newton 幕墙需要 `blocks`（时间/名称/密度/颜色），**缺一个适配层**。补上它，真实课表就能显示在幕墙上——Newton 也就从"视觉原型"变成"真实功能"。

**其他待办**：幕布换成整周排程（7 列 × 时段行）、数据接入后端画像与 RAG、手机端降级、清理旧的 `feat/demo` 分支。
