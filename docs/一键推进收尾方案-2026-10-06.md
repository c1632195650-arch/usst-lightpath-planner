## 3. 执行总约束（每个批次开工前重读一遍）

1. **三道命令的标准工作流**：开工 `node scripts/preflight.mjs`；每项收尾 `node scripts/impact.mjs`（或 `--print-command` 在 Bash 里跑）；提交前全量门禁 `node scripts/gate_overnight.mjs`。
2. **契约层（`src/types.ts` / `BuildWeekPlanInput|Result`）**：本方案**仅授权两处**结构性改动——P1-5 增活动量下限字段、P1-7(部分) 增 `mealWalkBudgetMin`（均为 `PlanRequest` 可选字段，见批次 5）。**每处必须在 commit message 里显式申报**（`契约: PlanRequest 增 xxx?`），禁止用 `any` 绕过。routineStore 接线走**已有**字段，不算契约改动。
3. **golden 纪律**：`evals/golden/` 只增不改。所有新行为用**新增测试**锚定；缺省路径（未配置/未采集）必须保持与现状零漂移——这是每个契约字段的验收点。
4. **不许改断言凑绿**：唯一例外是 R1 中 habitSpans 半边的源码锁适配，理由必须写进测试注释与 commit message（"适配移植现实，CY 裁决 R1"）。
5. **禁止**：push main、`git reset --hard`、rebase、`clean -fd`、删除任何文件、提交 `.env`/密钥/大文件/`dist/`、手工编辑 `data/` 下二进制（要改数据走 scripts 重放）、改动 golden 既有条目。
6. **行尾**：全仓 LF。新文件写完跑 `python scripts/normalize_eol.py --dry-run` 确认无 CRLF 混入。
7. **杂物隔离**：`.finance-tool-capability.json`、`.jw-proxy-capability.json`、`.legal-proxy-capability.json`、`.tyc-proxy-capability.json`、`.cluster/`、`.openclaw*/`、`HEARTBEAT.md`、`IDENTITY.md`、`SOUL.md`、`TOOLS.md`、`USER.md` 一律**不碰、不提交、不删除**（台账 §R 已登记为他人杂物/角色文件）。
8. **并行度**：如需开子智能体并行推进批次，**同时最多 2 个**；有依赖的批次（1→2→3、4→5）不得并行。
9. **提交纪律**：每完成一项独立提交一次（可独立回滚），前缀 `feat/fix/chore/docs(scope):`；**只提交，不 push**（push 仅批次 7.4 一次）。
