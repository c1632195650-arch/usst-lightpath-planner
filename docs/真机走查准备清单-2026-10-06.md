## 0. ⚠️ 先看这个：0.1.0 APK 是坏的，已作废

**2026-10-06 验收发现**：线上那个 0.1.0 APK **打包时漏了通知插件**，本地通知功能完全不存在。

| 证据 | 结果 |
|---|---|
| 已发布 APK 的 dex 内搜`localnotifications` | **0 次** |
| dex 内搜 `LocalNotification` | **0 次** |
| `mobile/android/capacitor.settings.gradle` | 只 include 了 `:capacitor-android`，**两个第三方插件都没进去** |
| 合并后 manifest 的 `uses-permission` | 只有 INTERNET，**没有 `POST_NOTIFICATIONS`** |

**根因**：`mobile/package.json` 没声明任何依赖 → Capacitor CLI 只扫 `mobile/node_modules`（当时不存在）→ **一个插件都没识别到**，但 `cap sync` 仍报"成功"（这是最容易骗过人的地方）。

**已修**：`mobile/package.json` 补依赖 + 建 `mobile/node_modules` 目录联接 → 复跑 sync 确认 `Found 2 Capacitor plugins` → 出 0.2.0。

> **教训**：`npx cap sync` 返回 "Sync finished" **不代表插件被打进去了**。判别方法见 §7。

**所以：如果你现在装 0.1.0，通知一条都不会响**，别拿它做走查。装0.2.0。

## 1. 电脑端准备

### 1.1 装华为手机助手（HiSuite）

| 项 | 说明 |
|---|---|
| 下载 | 华为官网 `consumer.huawei.com/cn/support/pc-manager/`（**别用第三方渠道**，Huawei HiSuite 正规名） |
| 安装位置 | 默认即可；**不要装到含中文/空格的路径**（HiSuite 自身会出问题，与本项目无关但会浪费你时间） |
| 首次启动 | 会弹「是否允许 USB 调试」类提示，允许即可 |

### 1.2 备一条数据线

**必须是数据线，不是纯充电线**。很多 Type-C 线只有电没有数据 —— 这是"连不上电脑"第一大原因。真要排查再用无线调试。

### 1.3 手机端设置（三处，缺一走查会白跑）

在**手机**上设置（不是电脑）：

1. **设置 → 关于手机** → 连点 7 次「版本号」→ 开启开发者模式
   （HarmonyOS 4 路径可能需输锁屏密码）
2. **设置 → 系统和更新 → 开发人员选项** → 打开「**USB 调试**」
3. **设置 → 应用 → 应用启动管理** → 选「光溯」→ **手动管理**，三个开关全开：
   - 允许自启动
   - 允许关联启动
   - 允许后台活动

> 第3 条是**通知能否活下来**的关键。华为的省电策略会把后台 App 掐掉，App 能收到但**不弹通知**——这是最典型的"看起来一切正常，就是不响"。

### 1.4 电脑侧编译环境（只在你改代码要重出 APK 时才需要）

已就绪，本次走查**不需要**重装：

| 工具 | 位置 |
|---|---|
| JDK 17 | `D:\Android\jdk-17.0.20.1+1`（`JAVA_HOME` 已 setx） |
| Android SDK | `D:\Android\Sdk`（`ANDROID_HOME` 已 setx） |
| Gradle | `mobile/android/gradlew`（阿里云镜像，勿改回google） |
| 签名 | `mobile/signing/lightpath.keystore`（gitignored，**别提交**） |
| 坑 | 仓路径含「学术部」中文 → `gradle.properties` 的 `android.overridePathCheck=true` **不能删**，删了直接构建失败 |

## 2. 装 APK

1. 手机用数据线连电脑，USB 模式选「**传输文件 / MTP**」（不要选"仅充电"）
2. 电脑上打开华为手机助手，它应能识别设备
3. 把 APK 传到手机（助手拖拽，或手机浏览器下载后自行安装）
4. 手机上「设置 → 安全 → 安装未知应用」→ 允许来自华为助手的安装
   （首次会提示"未知来源"，同意即可）

**APK 获取地址**（三种，任选）：
- 电脑：把 `dist/apk/lightpath-0.2.0.apk` 直接推给你

- 已上架页：`http://101.35.253.143/`（F18 检查更新会认新版本）

## 3. 走查前必须先做的一件事（数据从哪来）

**移动端是"网页端排计划 → 手机同步"的工具**，云上没有计划时 App 只会显示空态引导页（这是设计如此，不是 bug）。

所以走查前，**先在电脑网页端排好本周计划**：

1. 电脑浏览器打开 `http://101.35.253.143/`
2. 登录/录入课表（`Schedule`）→ 生成周计划
3. 确认网页端能看到今日块

> 走查登记表里注册后才有云端状态；空态那条分支已经由 e2e 覆盖，不必在真机上专门测。

## 4. 走查步骤表（对着界面元素逐条过）

登录后首页可见的锚点（便于你对照找）：「同步中…」「本周剩余概览」「现在/下一块横幅」「今天的安排有更新」。

### 阶段 A · 登录与同步（对着 4 个元素）

| # | 操作 | 期望 | 对应元素 |
|---|---|---|---|
| A1 | 注册新账号（昵称+密码，2~24位 / ≥6位） | 进今日页 | 登录页 |
| A2 | 看页头 | 显示「**同步中…**」后转为正常，周次正确 | `同步中…` / 第 N 周 |
| A3 | 下拉/刷新 | 今日块渲染，与网页端**一致** | 今日时间轴 |
| A4 | 断网再恢复 | 顶部出现「今天的安排有更新」 | 有更新横幅 |
| A5 | 退出重进（同一账号） | 能直接进今日页，不用重新登录 | — |

### 阶段 B · 轻编辑（写覆盖层，唯一写法）

| # | 操作 | 期望 |
|---|---|---|
| B1 | 点某个块 → 弹编辑面板 | 面板弹出，显示时间/地点/方法备注 |
| B2 | 顺延 **+15 分** | 卡片时间立刻 +15；块标记为已顺延 |
| B3 | 顺延 **+30 / +60** | 同上，六个快捷片都能用 |
| B4 | **完成**勾选 | 卡片出现「**已完成**」标记 |
| B5 | 重启 App | B2~B4 的改动**还在**（走的是本地覆盖层 + 云端双写） |
| B6 | 上网页端看 | 同一天同一块，时间与完成态一致（跨端一致） |

### 阶段 C · 通知（**本轮新增，0.1.0 验不了**）

⚠️ 通知走查**必须在有未来日程的时段做**。最省事的做法：把手机的系统时间**往前调 2~3 小时**，或排一个 20 分钟后的块。

| # | 操作 | 期望 |
|---|---|---|
| C1 | 首次打开 App | 弹出**通知权限**对话框（Android 13+ 必须）→ 允许 |
| C2 | 进今日页 | 若还有未来块 → 排程条数 = 剩余块 × 2 |
| C3 | 等待「**即将开始**」 | 块开始 **前 10 分钟**弹一条，标题形如「即将开始：14:00 高数作业」 |
| C4 | 等待「**现在开始**」 | 块开始**时刻**弹一条，标题形如「现在开始：高数作业 · 至 15:40」 |
| C5 | 下拉通知栏看**动作按钮** | 两条通知上都有「**✓ 完成**」「**顺延 15 分**」 |
| C6 | 点「✓ 完成」 | 直接生效（无需开 App），通知关闭 |
| C7 | 点「顺延 15 分」 | 该块时间 +15，通知重排 |
| C8 | 块进行中 | 有**常驻通知**「正在进行：×× · 至 HH:MM」（F15，静态文本不跳秒，**这是 v1 预期行为**） |

### 阶段 D · 白名单与已知限制（**最容易误判成 bug 的一段**）

| # | 操作 | 期望 |
|---|---|---|
| D1 | 展开「**提醒不响？点这里**」 | 出三机型路径：华为/鸿蒙、小米/其他、通用兜底 |
| D2 | **照华为那三条走一遍** | 启动管理三开关全开 |
| D3 | 完全退出 App → 等一个块开始 | 通知仍能弹（白名单已生效） |
| D4 | **重启手机** → 不开 App | ⚠️ **通知不会恢复**（AlarmManager 不持久，见 §6） |
| D5 | 重启后**打开一次光溯** | 通知排程恢复，D4 的限制消失 |

### 阶段 E · ICS 兜底（给不装 APK 的人）

| # | 操作 | 期望 |
|---|---|---|
| E1 | 展开 ICS 订阅区 → 复制链接 | 链接形如 `.../api/sync/plan.ics?token=...` |

## 6. 已知限制（先知道，免得当 bug 报）

| 限制 | 表现 | 定性|
|---|---|---|
| **手机重启后通知排程丢失** | 重启后不打开 App 就没通知 | **已知**（§8.2 风险登记）。缓解：引导页已写明 + 每次打开 App 全量重排。根治需原生 BootReceiver，stretch |
| 通知**不跳秒** | 常驻通知无每分钟倒计时 | **v1 预期**。每分钟跳动需前台服务，stretch |
| **非精确调度** | 可能延迟几分钟 | **有意设计**。不申请 `SCHEDULE_EXACT_ALARM`，规避 Android 12+ 权限深坑，符合"软提醒"定位 |
| 只排**当日剩余**块 | 明天的日程今天排不了 | 设计如此（`planTodayNotifications` 只看今天） |
| 重启手机后**覆盖层还在**吗 | 在（存localStorage + 云端） | 与通知无关，两回事 |
| 空态引导页 | 云端无计划时显示 | 设计如此，e2e 覆盖 |

## 7. 附录 · 怎么判断「插件真的打进包了」

**别信 `cap sync` 说"成功"** —— 它可能在 0 个插件的情况下也报成功。判别方法：

```bash
cd /d/WORKBUDDY*DATA/学术部/_work_dev

# ① sync 阶段：是否 Found N plugins（N 必须是 2）
cd mobile && npx cap sync android 2>&1 | grep -i "Found"
cd ..

# ② gradle 阶段：两个插件工程是否在
grep -c "implementation project(':capacitor-") mobile/android/app/capacitor.build.gradle
#   → 期望 2

# ③ APK 阶段：dex 里能否搜到插件类（最终判据）
.venv/Scripts/python.exe -c "
import zipfile
z=zipfile.ZipFile('dist/apk/lightpath-0.2.0.apk')
blob=b''.join(z.read(d) for d in z.namelist() if d.endswith('.dex'))
print('LocalNotification ->', blob.count(b'LocalNotification'), '次   期望 >=1')
"
```

> ⚠️ 排查时**别用 `capacitorjs` 搜** —— 那是 v2 的旧包名，v6 用 `getcapacitor`，搜了会误判成"插件完全没打进去"。

**如果 ③ 输出 0次** → 根因在 `mobile/package.json` 没声明依赖（本地 2026-10-06 就是这个坑，见 §0）。

## 8. 重出 APK 的完整命令（改了前端代码后）

```bash
cd /d/WORKBUDDY*DATA/学术部/_work_dev

# 0. 版本三处同步改（版本变更时）
#    mobile/android/app/build.gradle: versionCode +1、versionName
#    server/version.json
#    APK 文件名 lightpath-<ver>.apk

# 1. 构建前端（注意：vite 会清空 dist/，APK 要重新复制进去）
npm run build

# 2. ⚠️ 必须在 mobile/ 目录下跑，且 mobile/package.json 必须有依赖声明
cd mobile && npx cap sync android && cd ..

# 3. gradle 出包
cd mobile/android && export JAVA_HOME="D:\Android\jdk-17.0.20.1+1" \
  && export ANDROID_HOME="D:\Android\Sdk" \
  && ./gradlew assembleRelease --no-daemon && cd ../../..

# 4. 取产物
cp mobile/android/app/build/outputs/apk/release/app-release.apk dist/apk/lightpath-<ver>.apk

# 5. 上架公网
tar -czf - dist/apk | ssh ubuntu@101.35.253.143 'tar -xzf - -C /opt/usst/app'
curl -sI http://101.35.253.143/apk/lightpath-<ver>.apk | head -1   # 期望 200

# 6. 同步 version.json 到服务器（让 F18 检查更新认得）
scp -q server/version.json ubuntu@101.35.253.143:/opt/usst/app/server/version.json
```

**构建报错的两个高频坑**（勿改回去）：
- `non-ASCII characters` → `gradle.properties` 的 `android.overridePathCheck=true` 被删了
- 依赖解析超时 → `mobile/android/build.gradle` 的阿里云镜像行被改了
