## 1. 产品定位

**一句话**：面向上理工大学学生的**个性化学习规划助手**，帮你把"课表"变成"一份真的会执行的、允许休息的学期计划"。

**要解决的核心痛点**：不是"没时间"，而是"没有一份贴合自己节奏、且不会因为安排太满而三天放弃的计划"。

**形态**：Web 应用（响应式 + PWA），纯前端、无后端、数据本地存储。后续可经 Capacitor 打包成 App。

---

## 2. 目标用户与场景

- **用户**：上海理工大学在读本科生（MVP 先覆盖本院/主校区，天然支持全校）。
- **关键场景**：
  1. 开学初：导入课表 → 看一学期被切成哪几个阶段。
  2. 每周：看到"这周该做哪几件、留白在哪"。
  3. 期末前 21 天：自动进入冲刺倒计时，但**仍保留足够休息**。
  4. 跨校区上课：自动预留转场时间。

---

## 3. 核心差异化（答辩要讲的三个钩子）

| # | 钩子 | 说明 |
|---|---|---|
| 1 | **反内卷排程** | 所有时间管理产品都在帮用户塞满日程。本产品**考试周留白率不降反升（22%→30%）**，反差即记忆点（ADR-005） |
| 2 | **上理工原生** | 五校区跨校区转场缓冲、三学期制含短学期，通用 App 不会为我校定制 |
| 3 | **数据不出设备** | Local-First，课表与画像全存本地，架构层面消除隐私风险（ADR-003） |

> 可选加分：**光感知硬件钩子**（ESP32+BH1750，贴主题「智逐光影」）——但必须"失败不影响主线演示"，当前暂缓。

## 4. 功能需求（七大类，含优先级）

优先级：`P0 必做` / `P1 该做` / `P2 远期` / `⛔ 砍掉/暂缓`

### A. 输入层
| 功能 | 优先级 | 说明 |
|---|---|---|
| 课表导入：**PDF 解析（主）** | P0 | 教务导出 PDF → 前端本地解析（pdfjs-dist） |
| 课表导入：粘贴文本 / CSV | P1 | 兜底通道 |
| 课表导入：手动录入 | P0 | 最终兜底，解析失败必须能退到这 |
| 校历与学期设置（开学日/周次/短学期） | P0 | 阶段引擎前置输入 |
| 问卷画像（8–15 题，可观测行为） | P0 | 不用 MBTI（ADR-006） |

### B. 引擎层（核心算法）
| 功能 | 优先级 | 说明 |
|---|---|---|
| 学期五阶段划分（含短学期） | P0 | 适应→积累→加压→冲刺→考试周 |
| 课程优先级（可解释 `reason`） | P0 | 必须输出"为什么" |
| 周/日排程（贪心+疲劳惩罚+**强制留白**） | P0 | **最硬的一块，先写测试** |
| 留白率滑块 + "今天不想动"重排 | P0 | 差异化交互 |
| 期末冲刺倒计时（T-21/14/7/3） | P1 | 考试周自动切换 |

### C. 展示层
| 功能 | 优先级 | 说明 |
|---|---|---|
| 学期阶段时间轴（留白率曲线） | P0 | 一眼看懂产品逻辑 |
| 周视图 / 日视图排程 | P0 | "今天 2 件必须做 + 1 件可选 + 其余休息" |
| 优先级解释面板 | P1 | 配合"为什么" |
| 执行率统计 | P2 | 远期 |

### D. 校园特色（上理工原生）
| 功能 | 优先级 | 说明 |
|---|---|---|
| 跨校区转场 buffer | P1 | 五校区 + 短驳班车 |
| 短学期适配 | P0 | 三学期制独有 |
| 教室路径/校园地图示意 | P2 | 只做"不绑真实坐标系的示意图"，不碰测绘 |
| 食堂人流/口味推荐 | P2 | 远期数据服务 |

### E. 硬件钩子（光感知）
| 功能 | 优先级 | 说明 |
|---|---|---|
| ESP32 + BH1750 光照驱动建议 | ⛔ 暂缓 | 失败不影响主线 |
| 手动滑块兜底 | P0 | 无硬件时同样可用 |

### F. 社交/社区
| 功能 | 优先级 | 说明 |
|---|---|---|
| 兴趣圈子/论坛 | P2 | 微信小程序个人主体禁 UGC |
| 搭子/聚会/演出结伴 | P2 | 线下安全责任，建议剥离 |

### G. 技术底座
| 功能 | 优先级 | 说明 |
|---|---|---|
| PWA（可安装/离线） | P0 | HTML→App 的桥梁 |
| 本地存储（localStorage） | P0 | 数据不出设备 |
| AI 对话解读 | P1 | 规则引擎为主，大模型可降级 |
| App 移植（Capacitor） | P2 | 正式上线才做 |

## 5. MVP 范围（本轮就做这 4 件）

1. **PDF 课表导入**（失败可退手动录入）
2. **学期五阶段可视化**（留白率曲线）
3. **周/日排程 + 强制留白**（记忆点核心）
4. **轻量问卷画像**（影响排程权重）

**MVP 演示脚本（2 分钟）**：拖 PDF → 出学期阶段图 → 填问卷 → 展示留白周排程 → 切期末倒计时。

**明确不做（P2/暂缓）**：光感知硬件、社区/搭子、食堂/地图、AI 大模型、原生 App。

## 6. 技术架构

### 6.1 技术栈（已定，勿改）
| 层 | 选型 | 备注 |
|---|---|---|
| 框架 | Vite 5 + React 18 + TypeScript | 不用 Next.js（ADR-002） |
| 样式 | Tailwind CSS 3 | |
| 状态/存储 | React Hooks + localStorage（`lib/storage.ts`） | Local-First（ADR-003） |
| PDF 解析 | `pdfjs-dist` | 前端本地解析 |
| 测试 | Vitest（待引入） | M4 排程必须测试先行 |
| 部署 | Vercel / Netlify 静态托管 | 免服务器、免备案 |

### 6.2 架构原则
1. **本地优先**：所有数据存浏览器，不设后端、不碰账号密码（ADR-003）。
2. **规则引擎为主**：阶段/优先级/排程全用确定性规则，可解释、可复现；大模型只做解读且可降级（ADR-004）。
3. **可降级**：任何外部依赖（AI Key、网络、硬件）失效都不阻塞主线。
4. **契约先行**：`src/types.ts` 是唯一类型真相，锁死后任何改动需两人确认。

### 6.3 数据流（单向）
```
问卷/课表(PDF) ──┐
                 ├─> AppState(localStorage) ──> 引擎(buildPhases/priority/scheduler)
校历/学期设置 ───┘                                    │
                                                       ▼
                                              PhasePlan / CoursePriority[] / WeekPlan
                                                       │
                                                       ▼
                                            展示层(阶段轴/周视图/日视图)
```

## 7. 技术路线决策（已拍板）

| 决策 | 结论 | 依据 |
|---|---|---|
| 端 | **只做 Web + PWA**，不做原生 App、不套壳 | ADR-001 |
| 框架 | Vite+React，不用 Next.js | ADR-002 |
| 后端 | **纯前端无后端**，数据本地 | ADR-003 |
| AI | 规则引擎为主 + 大模型可降级 | ADR-004 |
| 课表导入 | **PDF 优先**，粘贴/CSV/手动兜底 | 教务支持导 PDF，门槛最低、我校定制点 |
| App 移植 | PWA（现在）→ Capacitor（上线）→ RN/Flutter（需原生能力） | 见 roadmap §3 |

### 7.1 PDF 导入专项
- 用 `pdfjs-dist` 前端解析教务导出的 PDF（不碰账号密码、不上传）。
- 解析成"星期×节次"网格 → `Course[]`（含周次 `1-16`/`1,3,5`/单双周），地点字段 → `campus.ts` 推断校区。
- **兜底**：解析失败必须退回手动录入，绝不卡死在 PDF。
- **前置**：D3 前取 1–3 份真实 PDF 课表样本校准（含跨校区课程）。

### 7.2 AI 接入
- 发送给 API 的内容**只能含课程名、时间、优先级**，不得含学号/姓名/班级/教师。
- 无 Key 必须完整可用（降级话术库）。
- 输出标注"AI 生成"。

## 8. 数据契约（核心类型，详见 `src/types.ts`）

| 类型 | 含义 | 关键字段 |
|---|---|---|
| `CampusId` | 五校区枚举 | `JG516`/`JG334`/`JG1100`/`FUXING`/`YINGKOU` |
| `Course` | 课程 | `name`/`timeSlot`/`location`/`weeks`/`examDate` |
| `Schedule` | 课表 | `courses`/`semesterType`/`startDate` |
| `Phase` / `PhasePlan` | 学期阶段 | `S0–S5`、留白率 `blankRate` |
| `UserProfile` | 画像 | `goalType`/`chronotype`/`energyCurve` |
| `CoursePriority` | 优先级 | `score`/`reason`（可解释） |
| `Task` | 任务 | `type`/`estimateMin`/`deadline` |
| `DayPlan` / `WeekPlan` | 排程结果 | `TimeBlock[]`（含 `blank` 块） |
| `ExamCountdown` | 期末 | `T-21/14/7/3` |
| `AppState` | 全局状态 | 上述全部 + `DEFAULT_APP_STATE` |

> **任何新增/修改字段，先改 `types.ts`，再改代码；禁止用 `any` 绕过。**

## 11. 合规红线（绝对不能做）

1. **不碰教务账号密码**——不写登录、不写爬虫、不放后端；课表由用户在浏览器本地粘贴/上传 PDF。
2. **不提交密钥/大文件**——API Key 只放 `.env.local`（已 gitignore）；演示视频不进仓库。
3. **校园地图只做示意图**——不绑真实坐标系、不导航（测绘法）。
4. **不做 UGC 社区**（本轮）——微信小程序个人主体禁发帖/评论/私信。
5. **不用 MBTI**（ADR-006）；心理/性格测评结果只存本地。
6. **不替用户做道德判断**——产品里不出现"拖延""效率低""落后了"这类词；留白调多高都是对的。

## 13. 给 agent 的开发与修复守则

### 13.1 开发新功能（照此流程）
1. 先读本文 + `AGENTS.md`，确认你认领的模块、文件所有权、红线。
2. 改动前先看 `src/types.ts`：需要的字段是否已有？没有则**先加类型**（并与对方确认，因为 types.ts 已锁死）。
3. 在**自己的文件/目录**内实现，不碰对方目录。
4. M4 排程：**先写 `scheduler.test.ts`，再写实现**。
5. 提交前跑 `npm run typecheck`，红字就修。
6. 小步提交，commit 信息用 `feat(模块): ...` / `fix(模块): ...` 格式。

### 13.2 修复 bug（照此流程）
1. 先跑 `npm run typecheck` + 读完整报错，别急着猜。
2. 定位到**具体文件与行**，只改局部，**不要重写整个文件**。
3. 改完立即 `typecheck` 复验；涉及排程的跑测试。
4. 若发现是 `types.ts` 字段问题，先沟通再动契约层。
5. 提交一个独立的 `fix(...)` commit，别把修复和功能混在一起。

### 13.3 三条铁律
- **不确定就问，别猜。** 尤其是合规边界与契约层。
- **可降级优先。** 新加的 AI/网络/硬件依赖，都要有"没有它也能用"的兜底。
- **完成 = 测试过 + typecheck 绿 + 可演示**，不是"代码写完了"。
