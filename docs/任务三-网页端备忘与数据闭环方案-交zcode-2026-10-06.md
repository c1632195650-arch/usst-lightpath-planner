## 一、背景一句话

产品闭环断了一环：用户在手机上想记一条待办，**手机上记完就结束了，网页端看不到**；网页端 AI 排计划时**不知道用户有哪些待办**，只能按课表和偏好排。CY 要求把这条链路打通：**手机记待办 → 网页端看见并补充 → 排计划时当硬约束 → 手机看到"已排进几点" → 勾完成回传**。

**本批性质：新增 + 契约扩展**。`SyncState` 加 `todos[]` / `goals[]`（**CY 已于2026-10-06 批准动契约**）。

## 三、数据模型设计（**这是本任务的地基，务必按此实现**）

### 3.1 `todos[]` 与 `goals[]`（新增，schemaVer 2）

```ts
// 放src/features/mobile/lib/types.ts（移动端契约）或独立共享文件；
// ⚠️ 严禁放 src/types.ts —— CY 红线：types.ts 零改动

type TodoKind = 'recent' | 'longterm';
// recent = 最近待办（打好勾即完成，不填时间）
// longterm = 中长期待办（勾时必须填完成时间，防遗忘）

type TodoCompletion = 'done' | 'snoozed' | null;

interface Todo {
  id: string;                // 稳定 uuid（跨端一致）
  kind: TodoKind;
  title: string;             // ≤120 字
  note?: string;             // 长文本（网页端可补，手机端可空）
  tags?: string[];           // 网页端可加
  createdAt: string;         // ISO
  // 🔴 中长期待办勾完成时必填；短期待办不填
  plannedDone?: string;      // 粗粒度，如 '2026-09-上旬' | '2026-09-中旬' | '2026-09-下旬'
  actualDoneAt?: string;     // 实际完成时刻（ISO），供「拖延指数」算
  completion: TodoCompletion;
  // 关联：排计划后可回填「已被排进哪个块」
  scheduledBlockId?: string;
  goalId?: string;           // 可选，归属哪个目标
}

interface GoalMilestone {
  id: string;
  title: string;
  done: boolean;
}

interface Goal {
  id: string;
  title: string;
  why?: string;              // 为什么重要（价值观锚定）
  milestones?: GoalMilestone[];  // 目标→里程碑→待办 三级
  createdAt: string;
  archived?: boolean;        // 归档而非删除
}
```

**为什么长期待办要 `plannedDone`（CY 原话：「长期的是怕用户忘掉完成时打勾而设定的」）**：
强制留痕 → 任务二可用它算「拖延指数」（实际完成 vs 计划完成）。粗粒度即可（CY：「粗糙一点比如 2026 年九月上中下旬」），不做精确到日。

### 3.2 契约扩展与前向兼容（**红线上最易出错处**）

- `SyncStatePayload` 加 `todos?: Todo[]` / `goals?: Goal[]`，**均可选**（旧客户端不发→ 服务端按缺省处理）
- `schemaVer`升 **2**；服务端 `SCHEMA_VER` 同步改2
- **服务端兼容策略**（必须实现，否则旧 App 会 400）：
  - 收到 `schemaVer < 2` → **接受**，只同步原有字段，`todos/goals` 保持库中原值不动（**不覆盖、不清空**）
  - 收到 `schemaVer > 2` → 返 400（不认识的高版本不能瞎猜）
- **客户端兼容**：`GET /api/sync/state` 返回 `schemaVer=2` 且含新字段时，**旧客户端必须忽略未知字段**（现有实现靠 JSON 反序列化天然容忍，但需加测试锁住）

### 3.3 LWW 与并发（**复用现有实现，不重写**）

`server/sync.py:92-133` 已有 LWW（`clientUpdatedAt <= serverTs` → `accepted:false` + 返回服务端副本），且带单调时钟保护（`new_ts` 不倒退）。本任务**沿用**，不新写冲突消解。

⚠️ **⚠️ 但 `todos[]` 是数组，数组级 LWW 会丢并发写入**（手机勾待办 + 网页端加待办同时发生 → 一方被拒）。请在 BLOCKERS.md 记一条**待 CY 裁决**并按最简方案实现：
- **最简方案**：`todos` / `goals` **按 id 逐项LWW**（每个 todo 记自己的 `updatedAt`，只合并真正更新的项），而非整数组覆盖
- 若实现成本过高 → 先整数组 LWW，但**必须在 BLOCKERS.md 明确登记为已知限制**（不得静默）
