
**所以拉完代码后：没有构建产物，也没有业务数据。** 这是设计如此，不是遗漏。

### 启动步骤

```bash
cd usst-lightpath-planner
npm install        # 装依赖
npm run build      # tsc --noEmit && vite build → 生成 dist/
python serve.py    # 启动，浏览器打开 127.0.0.1:8000
```

（或 `npm run dev` 走 5173 的 dev 模式，不需要 build）

### ⚠️ 你看到的界面会和我本地不同 —— 这是正常的

| 维度 | 说明 |
|---|---|
| **画像** | 各自问卷结果不同 → 排程参数不同（这是「因人而异」的设计目标） |
| **课表** | 各自导入的不同 → 块的位置不同 |
| **目标 / 目标偏好** | 存在各自浏览器的 localStorage + `lightpath.db` 里 |
| **数据积累** | `behaviorLog` / 成就统计各是各的 |

**所以不要用「界面是否一致」判断代码是否正确** —— 环境数据不同，输出本来就该不同。

### 用测试验证逻辑一致性（这才是该看的地方）

```bash
npm run typecheck    # 预期 0
npm run test:engine  # 预期 365 pass / 0 fail
npm run test:ui      # 预期 164 pass / 0 fail
node --import ./scripts/register-alias.mjs tests/p0-check.ts        # 预期 26 通过 / 0 失败
node --import ./scripts/register-alias.mjs tests/golden-compare.ts  # 预期 5/5 快照通过
```

**golden 5/5 是关键** —— 它保证「同一份输入 → 同一份输出」，
即**排程逻辑逐点一致**。这才是不受环境数据影响的验证方式。
