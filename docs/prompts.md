# 提示词库

> 好用的提示词存这里，两人共用。**用完觉得有效就补进来**，觉得无效就删掉不要留着。
> 核心方法论：**给 AI 的上下文越多，它生成的代码越能直接用。**

---

## 通用前缀（每段提示词都带上）

```
你在开发「光溯 · 上理生涯规划助手」—— 一个面向上海理工大学的
学习规划 Web 应用，参加第 18 届光电杯。

技术栈：Vite + React 18 + TypeScript + Tailwind CSS 3.4
约束：
  · 纯前端，无后端。数据存 localStorage。
  · 移动端优先（手机竖屏），桌面居中 max-width 560px。
  · 不要引入新依赖。
  · 严格使用 src/types.ts 里定义的数据结构，不得改名、不得自行新增同义字段。
  · 路径别名 @/ 指向 src/。

数据契约：
  <把 types.ts 相关部分粘进来>
```

---

## T1 · 生成组件

```
<通用前缀>

请实现组件：<文件名>.tsx

功能：<一句话>
Props：<列出 props 及类型>
验收：<什么算做完了>

要求：
1. 只操作上面给出的数据结构
2. 空状态/加载态/错误态都要处理
3. 移动端优先，触控目标不小于 44px
4. 输出完整单文件代码

最后，另起一段用一句话说明：你做了哪些我自己需要确认的假设。
```

> **为什么最后一句重要**：AI 经常默默替你做决定（比如默认时区、默认排序算法）。
> 让它主动说出来，你才知道哪里要人工把关。

---

## T2 · 调试（不要给太少上下文）

```
报错信息：
<完整粘贴，不要截图，不要省略>

相关文件完整代码：
<贴整个文件，不是只贴那几行>

我已经试过：
1. <方法>
2. <方法>

请先用一句话判断最可能的原因，再给出修复。
**不要重写整个文件** —— 只给出需要改动的那几行和具体位置。
```

> **为什么加粗那句**：AI 默认倾向于重写整个文件，会顺手改掉你不想动的地方，
> 然后引入新 bug。限定它只改局部。

---

## T3 · 算法审视 ⭐ 最值钱的一个

```
这是我们的排程算法输出：
<贴真实输出，不要简化>

对应的输入是：
<贴输入>

请你扮演一个「每天只上 3 节课、还想打篮球的大二学生」，
审阅这份日程，列出所有不合理的地方。

要求：
· 只挑毛病，不要改代码
· 按严重程度排序
· 每条说明为什么不合理
```

> **为什么这个最有价值**：AI 写算法不会告诉你它排得不合理，
> 但它换成用户视角审阅时挑得很准。D9 调参那天请大量使用。

## T4 · 写测试（M4 必用）

```
请为这个函数写 Vitest 单元测试。

要求：
· 至少覆盖：正常输入、空输入、只有一个元素、极端值（如每周 0 小时可投入）
· 断言具体数值，不要只断言"不为空"
· 不要用 mock，这是纯函数
```

---

## T5 · 让 AI 解释而不是代劳（学习用）

```
请用小白能懂的话解释这段代码在做什么：
<代码>

要求：
· 先一句话总结
· 再逐行/逐块说明
· 不要用术语，必须用术语就顺便解释术语
· 最后告诉我，如果我想改 <某个行为>，该动哪里
```

> 20 天里你们一定会遇到看不懂的代码。别跳过，**用这个模板花 5 分钟搞懂**，
> 比复制粘贴 10 次更有价值——尤其答辩时你要能讲清楚自己的实现。

---

## T6 · 写申报书某章节

```
我在写光电杯申报书的「<章节名>」部分。

项目背景：
· 面向上海理工大学的 AI 学习规划助手
· 核心差异化：① 反内卷排程，允许大量休息 ② 五校区/短学期定制
· 技术：纯前端 Local-First，规则引擎 + 大模型降级方案

要求：
· 300 字以内
· 语气专业但不吹嘘，不要出现"革命性""颠覆""全球领先"
· 要能被评委追问时不露馅

输出后，另起一段列出：评委看到这段话最可能追问的 3 个问题。
```

> **最后那句非常重要**。让 AI 提前帮你押题，比写完才发现答不上来强。

---

## 反面清单：这些提示词会得到垃圾结果

❌ "帮我写个课表导入功能" —— 没有数据契约，它会自己编一套字段名  
❌ "这个报错了怎么办" —— 不给代码不给错误栈  
❌ "优化一下这个算法" —— 没有"什么叫好"的验收标准  
❌ "重新写一遍" —— 它会丢掉你已经调好的细节  
❌ 一次让 AI 做三件事 —— 拆成三次，每次确认后再继续
